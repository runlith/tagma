# Frontend on Layer and Query

A client app is one graph of services: a feature declares what it needs, the composition names who provides it, and the graph gives each instance a lifetime by its tier. Sources: `packages/layer/src` (graph, bindings), `packages/query/src` (repos, queries), `apps/tagma/app/src/lib/wire` (server doors), `apps/tagma/app/src/lib/app/runtime.ts` (composition). When this file and the source disagree, the source wins. What a person sees — marks, color, tokens, words, mockups: `tagma-design`. Code that imports `effect` (Door and Live internals): load `effect4`; its "service is closures" form is for Effect `Context.Service`, not for Layer keys below.

## Assembling the app

**Keys.** A service is a class extending `Service<Self>()('Id', { tier })` (`packages/layer/src/key.ts`).
- `static make()` builds it; `static *make()` takes dependencies with `yield* Key` and passes each to its own constructor parameter (`apps/tagma/app/src/lib/features/power/Pace.svelte.ts`). `yield* Scope` is the instance's own scope: `scope.defer(...)` runs when the instance goes (its tier's scope closes or its condition drops). `yield* X.optional()` answers a key the manifest may provide only under a condition: the instance, or `undefined` where it does not stand, read once when the reader is built — the reader is not rebuilt when the condition flips, so use it for conditions fixed for the window (a host capability by `Host`) and `find()` at the place of use otherwise (`app/keys/Keymap.svelte.ts`, `app/chrome/ProjectCreation.svelte.ts`).
- A key without `make` is a port: the composition fills it with `Layer.of` or `Layer.provide`. A port's shape is an interface its owner declares (`features/plugins/windows/ViewWindows.ts`: `Service<WindowPort>()`).
- `Presenter<Self>()` is an eager service (`app/chrome/FrameState.svelte.ts`). `{ eager: true }` builds the key when its scope starts even under lazy building; the browser builds eagerly by default (Graph `data: 'eager'`), the server and `data: 'lazy'` tests build on first resolve.
- `{ deferred: true }` + `Layer.load(Key, () => import(...))` ships the code as a chunk; `X.use()` then answers a `Deferred`: `.current` (undefined until the chunk lands) and `.ready`. A component reads `.current`, never awaits it: see Svelte mode below.
- `Screen<Self, Options>()('Id', { tier })` (`@runlith/layer/svelte/screen.svelte`) is one instance per mounted component: `X.mount(options)` in the component's init, `X.use()` below it; it lives in a section of its tier's scope and closes with the component (`features/graph/TreeScreen.svelte.ts`).

**Tiers and the ladder.** `tier` is `'app'`, a rung name, or a rung's kind. The app declares its rungs in `src/app.d.ts` (`interface Ladder` in `@runlith/layer/key`) and lists them parents first in `App.define(manifest, { ladder: [ProjectRung, ThreadRung, GraphRung] })`. A rung: `Rung.define<Input>()('name', { keyOf, under?, kinds?, kindOf?, always? })` (`features/workspace/GraphRung.ts`). Its source is an app-tier key filled by `GraphRung.from(keys, read)` or `ThreadRung.of(read)`, placed in a feature layer; a scope's place is the parent's place plus `keyOf(input)`: while the source answers the same key the scope stands, a different key opens the next place and retires the old one unless a holder keeps it, and `undefined` closes the rung and the rungs under it. `GraphRung.Current` is the input as a key of the rung's tier (`(yield* GraphRung.Current).projectId`). An instance lives in the scope of its tier: app keys for the window's life, a project-tier key once per open project scope. A key may require keys of its own tier or above; a lower one is a type violation where the manifest's closure is checked, and `TierMismatchError` at run time.
- `App.hold(rung, input)` in a component keeps that place open and resolves its keys there (`features/projects/WarmHold.svelte`); `app.hold(...)` returns `{ scope, release }` outside a component (`features/threads/thread/ThreadLease.ts`).
- A rung move invalidates every load that depends on `layer:<rung>`.

**Manifest and composition.** A feature exports one layer: `Layer.mergeAll(Key, Repo, RungSource, ...)` (`features/workspace/layer.ts`). The composition merges feature layers and fills ports: `Layer.provide(Key, function* () { ... })` picks a filler from other keys, `Layer.of(Key, value)` gives a made value (`runtime.ts`: `ThreadOnScreen` by `Host.kind`, `ViewWindows` by `Host.isDesktop`, `Cache.of(...)`, `Host.of(hostOf(...))`, `ServerOrigin.of(...)`). A directly listed key on a tier off the ladder throws in `App.define` (keys under a condition or in a chunk when admitted); two providers of one key, a bare port in the manifest or a repeated id throw when the app opens. A manifest that does not close against its world (`App.load`, `App.handle`, `test`) is a type error naming `'manifest misses'`.

**Conditions.** `Layer.when(Key, (value) => boolean, layer)`, `Layer.when([A, B], (a, b) => ..., layer)`, `Layer.when(SomeRung.present(kind?), layer)` or `Layer.when(() => boolean, layer)`; the layer may be a loader `() => import(...)`. The keys under it exist while the predicate holds; a component takes them with `X.find()`, a `make` with `yield* X.optional()` (both answer `undefined` otherwise). The type gates on `use()`/`find()`/`Screen.mount` (`packages/layer/src/door.ts`) switch on only when the app declares `interface Manifest { readonly app: typeof runtime }` in `@runlith/layer/door`; `apps/tagma/app` does not declare it, so a wrong `use()` fails at run time: `UnknownServiceError` for a key not provided there (a condition that does not hold), `RungClosedError` for a closed rung, `TierMismatchError` for a scope outside the key's tier.

**Ambient keys** every app has (`App.ts` adds them unless the manifest provides its own):
- `Prepare(rung, input)` prefetches the chunks of that place before its source moves (`features/projects/Prefetch.ts`).
- `handoff.onLeave((rung) => ...)` fires before the next scope of a rung opens, `handoff.onClosed((scope) => ...)` after the gone scope's keys are released; both return an unsubscribe for `scope.defer`. An app-tier owner of per-scope state releases it there (`Cache.of` in `packages/query/src/repo.ts`).
- `Failure.report(error)` receives service build failures and what owners report; default rethrows in a microtask, `Failure.of(report)` replaces it.
- `Snapshot.part(Layer.provide(Key, () => ({ take, apply })))` carries state from a server load to the browser in the `__layer` field of load data; `Cache.of` registers the query cache this way.

## Data

**Server doors** (`lib/wire`, filled by `WireLayer`):
- `Door.perform(id, input, lens, { signal, keepalive })`: `id` is an operation of the server catalog (`HttpOperationId`), input and answer are typed, encoded and decoded by that operation's schemas, `lens` is `{ project?, branch?, scope? }`. Failure rejects with `Refusal` (`wire/refusal.ts`: `code`, `reason`, `unblock`, `words`); `toldOf(error)` turns any failure into what a surface shows.
- `Door.ask((api) => api.group.endpoint({...}), options)` calls an `Api` endpoint outside the catalog (thread upload in `features/threads/Repo.ts`).
- Binary routes (checkout picture, file preview, call audio and peaks, thread attachment) are `Api` endpoints too: `Door.address((routes) => routes.group.endpoint({ params, query }))` builds the URL on the server door for `src`/`href` (`checkout/Repo.ts` `pictureAddress`), `Door.address(path, lens)` resolves a path the server handed out (`threads/native/ThreadUploads.ts`), `Door.bytes(address, { signal })` reads it as a `Blob` rejecting with `Refusal` (`checkout/PictureDiff.svelte`). `Door.exchange(endpoint, payload, schema)` posts JSON to an `endpoint(...)` declared outside the `Api` (`devices/pair.ts`).
- `Door` sends through `Platform.fetch` to `ServerOrigin.http`; `Live` opens `Platform.socket` at `ServerOrigin.socket(path)`; `SoundChannel.open(listening, track)` is the binary dictation socket (`speech/dictation/Sender.ts`).
- `Live` (shape `LiveConnection`) is the shared socket (`channel: 'separate'` gives one subscription its own): `live.hold(client => client['feed.id'](input), onItem, onFailure, resume?, ending?, channel?)` returns `{ unsubscribe }`; hold in the service's constructor and `scope.defer(() => held.unsubscribe())` (`features/workspace/ProjectsFeed.ts`). `live.call(work)` answers a Promise rejecting with `Refusal`; `live.attempt(work)` an Effect failing with `CallFailed { refusal, sent }` (`features/threads/ThreadPort.ts`).
- New operation: declare it with `doors: { http: 'perform' }` among the declarations its server module's `contract/wire/module.ts` loads (`plugin-secrets/contract/wire/operations.ts`), implement its body among the pairs the module manifest's `bodies` loads (`plugin-secrets/plugin-secrets.ts`, `plugin-secrets/operations.ts`), then call it through `Door.perform` from a repo. New subscription: the server module declares `feed('x.subscribe', { input, event, refusals, callers })` and serves it with `liveOf`; the app adds the feed constant to `USED` in `lib/wire/liveGroup.ts` and reads `client['x.subscribe']`.

**Repos** (`@runlith/query/repo`): `Repo.define('id', ({ single, keyed, mutation }) => ({ ... }), { tier, door: Door })` is a service key whose fields are queries (`features/plugin-secrets/Repo.ts`).
- `single({ loader: ({ signal }, door) => door.perform(...), staleTime?, gcTime?, refetchInterval?, live?, initialPageParam?, getNextPageParam? })` → `SingleQuery`; `.page({ page, pageSize? })`, `.inf({ pageSize?, initialPageParam? })` (infinite, paged by the config's `getNextPageParam`), `.all()`.
- `keyed({ loader: ({ key, signal }: KeyedLoaderContext<K>, door) => ... })` → family: `.key(k)`, `.all()`, `.where(match)`, `.reset()`.
- `mutation({ mutator: (variables, { signal }, door) => ..., concurrency? })` → `.run(variables, { throwOnError })` answers data or `undefined` (a failure sets `.error` either way; `throwOnError: true` also rejects), `.pending`, `.status`, `.reset()`.
- Query names carry the scope's place: a project-tier repo keeps one namespace per project scope, and a closed scope's queries are removed. `live: true` gives each query built from it, in the browser, its own observer from construction to the end of its scope, reader or not (polling and focus refetch run alone); a server render never observes.
- Tuning goes in the manifest: `Repo.tune(Repo, { field: { staleTime, ... } })`. Client defaults: `Cache.of({ defaultOptions })` in the composition (`runtime.ts`: retry by `retriable`).
- Reading: components and service effects that consume a query read `.data`, `.error`, `.isFetching` (`features/plugin-secrets/Section.svelte`, `features/speech/dictation/Dictation.svelte.ts`); the first reader opens the observer that fetches and holds the entry. Keep that owning read before selecting a mutation's overlay. `watch()`, `watchError()`, `watchFetching()` follow the entry without holding it — for feeds, badges and guards. `gated(() => query | undefined)` (`@runlith/query/gated.svelte`) adds `.isDisabled` over a query that may not exist yet.
- Failure lifecycle: `undefined` data can mean pending or refused, not “fetch again”. Do not call `load()` or `refresh()` from an effect that tracks the same entry with `watch*()` or reactive getters: cache transitions rerun it, and wrapping the fetch in `untrack` leaves the tracked read in place. Let the observer fetch and retain the refusal in `.error`; retries belong to the repo/cache policy. Further requests follow explicit intent, invalidation or observer policy, never an absent-data loop. Fix such a loop at its reader, without throttles, retry flags or changing the kit's explicit `load()` semantics.

## Effects that write shared state

A service on `app` or a rung tier is shared by every component that takes it, and one component is often mounted several times at once: the same page in the main pane, in a side tab and in a thread's tab; a row in an outline, a tree and a shelf; one window per project. An `$effect` that writes into such a service is one writer among several.
- Converge. Every write must reach a state from which each writer's next run writes nothing: writing the value already there is a no-op, and writers holding different values of one entry settle on one by an order the value has — the later stamp, the higher id, the union of sets. A write where each instance asserts its own value — move mine to the front, set the slot to mine, toggle, count up — makes two mounted instances rerun each other until Svelte stops the flush with `effect_update_depth_exceeded`.
- An event is written where it happens. A visit, an opening, a "seen", a creation is written once: in the arrival branch of an effect (its subject differs from the last one this instance held), in a handler, or after the load that brings it. An effect body reruns on every change of anything it read — a live update, a rename, a refetch — and re-asserts whatever it writes each time; what it writes on every run is only what follows from the current state.
- An effect depends on every reactive read made while it runs, including reads inside the methods it calls. A write method that reads its own state first — read-modify-write, iterating a `SvelteMap` or `SvelteSet`, serializing a whole record — subscribes the calling effect to its own output. Never assume an effect "only writes": read what the called method reads.
- Fix the shape of the write at its owner. `untrack` around a write that does not converge hides the loop and keeps the re-assertion, and so do a guard flag, a debounce or a try/catch around the boundary; `untrack` is for a value the effect deliberately does not follow.
- The same holds beyond one flush: two windows answering each other's storage `watch`, or two instances each replacing the address with their own, trade the write forever without even the depth error to stop them.
- Diagnosis. In a development build, which tests run, the depth error is preceded by the stacks of the writes that kept the flush going: the producer is named there. In production the error goes to the boundary of the last effect scheduled, so the pane showing the failure need not be the one whose effect loops; several panes failing together point to instances contesting one service.

## Reads never write

Svelte refuses any state write while a `$derived`, a template expression or a block (`{#if}`, `{#each}`, `{#await}`, `{#key}`) computes: `state_unsafe_mutation`, whatever the compile mode. `untrack` lifts the refusal and a plain `$effect` may write. So everything a component may read there — a getter, a query's `.data` or `.promise`, a service's answer — writes no state, directly or through work it starts.
- A read changes nothing it reads from: no re-configuring an observer, no "sync and notify" on the way out. A read that moves its own source reruns itself forever.
- A bridge from an outside source into Svelte state — a query-core cache listener, a socket, an emitter — counts on the source calling back synchronously inside the stack that triggered it, which may be a reader's derived. It delivers synchronously when `$effect.tracking()` is false and in a microtask otherwise (`deliver` in `packages/query/src/core/deliver.svelte.ts`). Outside work a read must start goes into `createSubscriber`'s start, which Svelte runs untracked.
- A method that changes state — `load`, `refresh`, `setCache`, `reset`, a mutation's `run` — is called from a handler, an `$effect` or after an `await`, never from markup or a derived.
- Diagnosis. The stack of `state_unsafe_mutation` runs from Svelte's `set` down to the reader. The first frame of our code above `set` is the producer to fix; the component at the bottom only read.

## Environment

**Owners.** Environment facts and capabilities reach a feature only as keys:
- `Host` (`packages/layer/src/Host.ts`): `kind` (`'tab' | 'desktop' | 'mobile'`), `os` (`'macos' | 'ios' | 'windows' | 'linux' | 'unknown'`), `isDesktop`, `apple` (macOS or iOS), `touch` (coarse pointer without hover), `installed` (standalone display mode). Filled by `runtime.ts` (`hostOf`) from the bridge, `navigator`, the stored shell choice and media queries.
- `Platform` (`Platform.ts`, browser filler `Platform/browser.ts`): `storage.local` / `storage.session` (`getItem`, `setItem`, `removeItem`, `watch`), `cookies`, `fetch`, `socket`, `databases` (IndexedDB), `locks` (Web Locks or `null`), `languages`, `userAgent`, `kind`, `isBrowser`.
- `Router` (`Router.ts`, filler `RouterLive` in `sveltekit/index.ts`): `url`, `pathname`, `routeId`, `params`, `status`, `data`, `goto`, `replace`, `invalidate`, `historyIndex`, `traverse`, `reload()`, `load(href, { replace? })` (full document load), `onNavigate({ before?, after? })` answering an unsubscribe (`app/chrome/Shell.svelte`); the listeners hear navigations once `App.mount` attached the router. The server router refuses `goto`, `reload` and `load`.
- `Theme` (`lib/shared/Theme.svelte.ts`): `choice`, `mode`, `choose(next)`, `paint()` (Root paints the `dark` class); readers of the theme take `Theme.mode`.
- `ExternalLinks` (`lib/shared/ExternalLinks.ts`): `open(url)` outside the window. `FileSaver` (`lib/shared/FileSaver.ts`): `save(blob, filename)` as a download. `SystemSettings` (`lib/shared/SystemSettings.ts`): `open(page)` of macOS privacy settings, provided only on the macOS desktop.
- `ClientBuild` (`lib/wire/ClientBuild.ts`): `behind()`, whether the window's build lags the served one.
- `ServiceWorkers` (`lib/shared/workers/ServiceWorkers.ts`, filler `BrowserWorkers.ts`): register/unregister, notification permission, push subscription, notices, badge, worker messages.
- Desktop bridge ports (`lib/shared/desktop/`): `DesktopTabs`, `DesktopBrowser`, `DesktopDictation`, `DesktopFolders`, `ProjectWindows`, `MainWindow`, each typed by its `@tagma/desktop/bridge` contract and provided only on the desktop.
- `ServerOrigin` (`lib/wire/ServerOrigin.svelte.ts`, filled by `runtime.ts`): the server door the window came through — `http`, `socket(path)`, `local` (loopback), and `artifacts`/`sandbox` declared from `/health`; `artifact(href)` is an artifact link's address through this door.
- `Door` and `Live` for the server.

**Norm.** Only the composition (`runtime.ts`) and the fillers of the owning keys read browser and bridge globals:
- `window.tagmaDesktop` (declared in `apps/tagma/desktop/src/bridge.ts`): only `runtime.ts`.
- `fetch`, `WebSocket`, `EventSource`, `XMLHttpRequest`: only `Platform` (its defaults in `Platform.ts`, the browser filler) and `service-worker.ts`; `lib/wire` takes them from `Platform`.
- `localStorage`, `sessionStorage`, `indexedDB`, `navigator.locks`: only `Platform`.
- `location`, `history`, `$app/navigation`, `$app/state`: only `@runlith/layer/sveltekit`, `runtime.ts` (`ServerOrigin`, `ClientBuild`) and the `Platform` cookie filler's `location.protocol`. `$app/environment` constants are free.
- `navigator.platform`, `userAgent`, `userAgentData`, `language(s)`, `standalone`, `matchMedia`, `window.open`: only `runtime.ts` and the `Platform` filler; `Theme` keeps its system-theme `MediaQuery`. `navigator.serviceWorker`, `PushManager`, `Notification`: only `BrowserWorkers`.
- In a load, read the environment with `yield* Host` (`routes/+layout.ts`).

Legitimate direct reads (one API in every shell): `navigator.clipboard`; `navigator.userActivation` in a view bridge method; the microphone and `AudioContext` in `features/speech/dictation/Sender.ts`; facts and events of the document the app draws into (`devicePixelRatio`, `document.fonts`, selection and `execCommand`, window size, focus and visibility, pointer listeners on `window`, the WebGL probe); `Live`'s page-life listeners; `Root.svelte` binding `pagehide` to `Door.markLeaving`; link-click interception on `document` by its owner; `fetch` of a `data:` URL (decoding); `features/views/reach.ts` (reachability of a foreign origin); `service-worker.ts` (no graph); `app.html` reading the theme before the bundle; `lib/app/renamedKeys.ts` until the rename ends.

**Declaring a door or a host capability.** A door is a port with one subject, its shape declared by its owner, filled in the composition by environment:
- With a real web counterpart: an unconditional key, filler chosen in `runtime.ts` (`ViewWindows` → `NativeWindows` over the bridge on the desktop, else `FloatingPanels`; `ExternalLinks` over `window.open`).
- Without one: provide it under `Layer.when(Host, (host) => host.isDesktop, ...)` (`DesktopLayer` and `SystemSettings` in `runtime.ts`); a component takes it with `X.find()` and handles `undefined` (`features/checkout/files/DesktopTabKeys.svelte`, `features/speech/dictation/MicButton.svelte`), a service with `yield* X.optional()` (`features/speech/dictation/Global.svelte.ts`).

**Kits.** `packages/chat-ui` imports neither layer nor query: it declares ports in its own contract (`src/wire/ChatConnection.ts`, `ChatEntryHandlers` with `attachmentUrl` and `readAttachment` in `src/entries.ts`, `ChatSurfaceRendering.touch` in `src/surface.ts`) and the app fills them (`features/threads/ThreadPort.ts`, `threads/native/ThreadUploads.ts` `attachmentHandlers`, `threads/native/Conversation.svelte` from `Host.touch`).

## SvelteKit bindings

- `@runlith/layer/sveltekit`: `export const load = App.load(runtime, function* (event) { const x = yield* Key; ... })` in `+layout.ts`/`+page.ts` (`apps/tagma/app/src/routes/+page.ts`). In the browser it opens the tab's app with `Platform` and `Router` fillers, declares `layer:<rung>` dependencies, applies the snapshot, runs the generator (yield keys or `X.optional()`, never `Scope`), and answers its data. `App.load(runtime, entry, run?)` first prepares and enters a `Layer.entry(id, loader)` chunk.
- `App.mount(runtime)` in the root component's init (`lib/app/Root.svelte`) publishes the app the load opened; descendants then call `X.use()` in their init.
- `App.mount`, `App.attach`, `App.override(key, value)`, `App.hold`, `App.section` run only in component init.
- `Router.goto` rejects before the first navigation landed.
- Server: `@runlith/layer/sveltekit/server` `App.handle(runtime, ({ event, resolve, app }) => ...)` opens one app per request with the request's `Platform` and `Router`.
- Prerender: SSR under `App.handle` fails for a prerendered page (`requestUrl` reads `url.search`). A page carrying the graph sets `ssr = false`; a layout that prerenders does not touch layer. `apps/tagma/app/src/routes/+layout.ts` sets `ssr = false`, `prerender = false`.

## Svelte mode and guarded branches

- Tagma compiles Svelte without async mode: `experimental: { async: false }` in the app's `svelte.config.js` and in every package Vite config. No `await` in markup, in `$derived` or at a component's top level (it does not compile), and no `fork` (it throws); data arrives through repos, and a screen that must appear whole holds its own first frame (`ready` on `BlockPage`, given by the route). Which Svelte hunks and tests are off with the mode, and how to turn it back on: the `svelte@5.57.0.patch` section of `patches/README.md`.
- `{#if x !== null}` over children that read `x` or its fields through props is sound for the branch's own effects when `x` is cleared outside the branch: a branch the condition leaves is destroyed or paused for its outro before any effect under it runs again, even when a teardown later in the tree clears `x` after the traversal passed the guard (hunk 10 in `patches/README.md`). A teardown inside the branch that clears `x` still lets the rest of that traversal run the branch's render effects over `null` (task e60a460d). A `TypeError` on a field of `null` thrown by an effect of a guarded branch is a scheduler defect: reproduce it beside the patch traps in `packages/layer/src/svelte` and fix it in `patches/svelte@5.57.0.patch`, never with `?.`, a snapshot or a one-item `{#each}` in the consumer. A prop read in an event handler or after an `await` is the live value, whatever the guard: a handler that clears `x` and then reads it reads `null`.
- A closure over a component's props handed to an owner outside its branch — a window claim, a tooltip trigger, a registry — runs in that owner's effects, which the guard does not reach: the owner of the guarded value publishes it (`PageClaims` in `routes/[project]/+page.svelte`).

## Tests

A double goes into `boot` under its own key, `Layer.of(Key, double)`, and the real provider stays out of `manifest`. `at` sets each rung's input.

The fixture rung `Visitor` is for kit tests only.
- `@runlith/query/testing`: `stubQuery`, `stubSingle`, `stubFamily`, `stubInf`, `stubMutation`, `stubAll`, `mountRepo(Repo, { door, queryClient, ladder, at })`. `@runlith/query/test-utils/observe.svelte`: `observe`, `observeDerived`, `observersCount`.
- App harness `lib/app/testing.ts`: `mountShell(manifest, boot, { at, thread, storage })` on the app's ladder, `testLive`, `liveFeed`, `slotWorld`.
- A consumer of `Door` or of a repo takes a double under that key. A test that runs the real `Door` hands it its transport, never a stubbed global: `testDoor(fetch)` from `lib/wire/testing.ts` (`features/graph/BlocksRepo.svelte.test.ts`), or `makePlatform({ fetch })` and `ServerOrigin.of(...)` in a graph's boot (`features/graph/GraphFeed.svelte.test.ts`), and awaits `loadOperations()`; a `LiveConnection` takes its socket factory and origin the same way (`wire/liveClose.test.ts`). `mountShell` boots a `ServerOrigin`.
- The unit projects default to `environment: 'node'` (`apps/tagma/app/vitest.config.ts`), where no `$effect` runs: a test of effects or components starts with `// @vitest-environment jsdom`.
- A component or service that writes shared state from an effect is tested with two instances mounted at once on different subjects, then a live update to one of them (`features/graph/block/BlockPage.svelte.test.ts`): one instance alone cannot show a contest.
- A read that must stay pure is tested inside a `$derived` under `$effect.root` and `flushSync`, with the other readers of the same source already standing (`packages/query/src/promise.svelte.test.ts`). A forbidden write then throws at once; a mounted page around it may stall instead of failing.
