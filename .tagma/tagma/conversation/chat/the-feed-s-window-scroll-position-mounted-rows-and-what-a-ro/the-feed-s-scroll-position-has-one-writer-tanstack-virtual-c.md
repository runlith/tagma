The feed's position is written only by tanstack virtual-core through [[8b7128c3]]; `TranscriptVirtualizer` gives it policy and commands. The shared binding carries the geometry, key-resolved measurement and mount-batch contracts of [[1fa34c88]]. A correction it cannot write — a finger down or momentum on iOS, a WebKit rubber band, or a press on the feed's scroller — it holds as shifted row starts and a total shifted by the same amount, and writes once in the first frame the write lands. A native scrollbar drag maps the pointer against that total: keeping the scroll extent fixed prevents its next move from undoing the correction. Overlay scrollbars expose no distinct hit region, so the existing scroller press holds writes until release, cancellation or window blur; releasing refreshes the library even when no scroll event follows. Tagma's own writers wrote through all of these: a prepend re-pinning loop cancelled only by wheel, touchmove or key ran for up to 180 frames against iOS momentum, which sends none of them.

- **Following is the library's end anchoring, switched by `anchored`.** While the feed follows and nothing holds it, `followOnAppend` is on and `scrollEndThreshold` is infinite, so every size change keeps the end; otherwise the threshold is minus infinity and the library never reaches for the end. Layout changes the library does not see as resizes — the composer's clearance, the scroller's size, a reshape it does not take for an append — call `scrollToEnd` while anchored, and so does every scroll event that leaves an anchored feed short of the end; while anchored no scroll event counts as the reader's ([[76fcb7d4]] gives the reason). Leaving it — a hold, the reader moving away — also cancels the library's outstanding tail command, which otherwise keeps retargeting the end under a selection.
- **Which size change moves the view.** A row ending at or above the layout position is compensated, the row under the top edge and every row below are not, so the row at the top keeps its offset. A row whose control the reader pressed is compensated exactly when the control moved within its row by the change, so a "show less" under its content keeps the control under the finger; the movement is read inside the row because, within one observer batch, an earlier compensation has already moved the screen while the row boxes wait for the notify.
- **Commands are the library's.** A select is `scrollToIndex` (the window re-aims it when rows land above, because the command holds an index), the tail is `scrollToEnd`, a wheel over the composer is `scrollBy`, and any input of the reader is `cancelScroll` first: a smooth command keeps retargeting through external scroll events otherwise.
- **A far select jumps, then glides one screen.** A smooth select farther than a viewport is an instant `scrollToOffset` to one viewport short of its row, then a smooth `scrollToIndex` started by the first scroll event within a viewport of that point. A smooth scroll across the whole distance mounts every row it passes and restarts from rest each time a measurement moves its target; a smooth `scrollTo` in the same task as the instant write overrides the write in Chromium; and waiting for the exact read-back leaves the select parked when a fling carries on from the written point. The window mounts the rows of the jump view and of the target view in the same task as the write, because a write from an input handler paints before its scroll event can mount anything; the rows behind the jump view, which neither the first frame nor the glide shows, stay out of that task.
- **The window is one viewport of content on each side of the visible rows**, in pixels from the laid positions. The library caches the mounted indices by the visible indices alone, so a measurement that leaves less than a viewport beyond them re-extracts the window. While the feed moves, the margin fills one new row per frame, nearest the view first, and while a select has not landed it takes no new margin row at all: every row in view mounts at once and a select's landing rows mount with its write, while a margin filled in one frame mounts several unmeasured rows in it, and a margin row measured above the view during a glide moves the glide's target. A row under an active touch stays mounted until the touch ends: removed, it takes the touch's remaining events with it, and the scroller never hears the finger lift.
- **A withdrawn top row** moves the view to the start of the nearest surviving row after it, else before it, searched over the whole previous order the library still holds; the library resolves its anchor by key and does nothing when the key is gone.
- **A key revision anchors an interior reshape; a width or font change needs size memory.** The library patch preserves the reading key when the model changes its key function, even with the count and edge keys unchanged. A width or font change re-estimates every row out of the window, so before it reaches the layout the window freezes the sizes of the unmounted rows above a paused reader as they stand; they correct on mount, with compensation.
- **A select owns the movement until it lands.** Once the view reaches its target, any later movement — the reader's or the browser's (find-in-page, focus) — ends the aim; otherwise rows landing above would re-aim the view back.

Measured sizes are kept per key with the content width, the estimate the row had when measured — the proxy for its content and disclosure — and the device-pixel and font epoch; a reopened thread restores only measurements fitting all of them. A row out of the window keeps its measurement when its content changes, and rows above a paused reader keep their sizes through a width change: dropping either would move the view with no compensation, while the mount corrects them with it.
