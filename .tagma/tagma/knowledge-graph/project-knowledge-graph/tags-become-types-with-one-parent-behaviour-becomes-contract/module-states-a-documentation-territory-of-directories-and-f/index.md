Part of [[6bf40362]]. It fixes how `#module` states the code it documents, for section 8 ([[e04cfdcb]]).

## Outcome
- `#module` is a type with the `core/territory` contract: a territory parameter of directories and files.
- A domain module is a descendant of `#module` — in the catalog or in the project — not a new value of a closed kind enumeration.
- The territory is **documentation ownership only**: it answers `read_owners` and the doctor's territory findings (`area-void`, owner-spread). The law's units come from selectors and manifests in the law's own policy ([[b29472e3]], [[bedb212a]]); no law snapshot is built from `#module` nodes.
- Section 1 ([[f658e190]]): runlith's `#module` nodes are descendants of `#module` with this contract and a territory.

Settled in the joint review with the law layer ([[6bf40362]] §11, point 1). The draft named the contract `core/boundary` and let the `modules` snapshot be built from it; both were withdrawn — the name read as the `boundaries` builtin, and hand-drawn module copies of imports had already rotted once.

## What holds now
`#module` kinds are `kit|product|surface|substrate` and its sources are `dir` only; a domain module inside a product cannot be expressed, and the doctor measures territory only by directories.

## Acceptance
- A `#module` with a file territory owns those files in `read_owners` and in the doctor's territory findings.
- A domain module is declared as a descendant type with no core edit.
- Adding or moving a `#module` changes no boundary-unit inventory; where it changes the reach of a container holding an adopted rule, that change obeys [[172759d0]] — pending, and re-adopted in the same change.
