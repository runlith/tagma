The server `browser` module (`apps/tagma/server/src/browser`, product) owns pages, profiles, hosts, and automation. The CDP protocol and Tagma-unaware automation primitives are the `@runlith/cdp` kit (`packages/cdp`).

**Module.**
- `contract/wire`: page and profile ids, operations, feeds, refusals.
- `contract/service`: `Pages` (registry and live state), `Profiles`, the `PageHost` and `ProfileHost` ports, the registry of connected hosts. Host adapters are their own modules, fill the ports, and declare themselves; composition wires them. The core neither lists adapters nor branches on them.
- Storage — entities tables in the module manifest:
  - profiles (machine-scoped): id, name, host adapter, adapter document (JSON; the adapter declares and validates the schema, the core does not read it), console capture (`auto`, `always`, `never`), marked-for-deletion, creation time;
  - pages (project-scoped): id, project, profile, context (empty — the profile's permanent context; a per-thread ephemeral context is stage 2), URL, title, favicon, opening thread, opening page (popup), history records for restore, downloads, last-activity time, closed or not.
- A page's live state — whether it loads, can go back and forward, crashed, answers, has a dialog open, is driven by an agent, is shown anywhere — stays in memory from host events and is published over the `browser.pages` feed.
- Settings: `browser.userProfile` and `browser.agentProfile` (project over operator value), whether to open links in the built-in browser.

**Page.**
- The server issues the id. The host creates a popup itself — `setWindowOpenHandler` decides synchronously — and holds it under its own local key until the server answers; a popup opened while no channel exists arrives at reconciliation as a live page without a record and gets its id then.
- States:
  - `live` — a connected host holds it;
  - `dormant` — the host is connected, there is no live page (unloaded for memory or after a host restart); showing or an agent action restores it on that host from the record;
  - `away` — there is no host. While the host's last process lives (main reports its pid on connect), an action waits for its return without a deadline: that is a reconnect. With no process alive, the action refuses with `host-away`.
- Closed project pages stay as a "reopen closed" stack; the last twenty are kept, like the VS Code closed-editor stack, older records are deleted.
- A new page's profile is the named one, or `browser.userProfile` for a human and `browser.agentProfile` for an agent. There is no substitution: a profile whose host is disconnected answers `host-away`, and unblock names the connected hosts' profiles from the registry.

**Ports.**
- `PageHost` — one host's pages:
  - open (id, profile, context, URL or history records — where the host can restore them, otherwise the current URL), close, list live ones — reconciliation after reconnect;
  - go, back, forward, reload, stop — each host its best way: desktop via `loadURL` and `webContents` history without CDP, managed Chromium via CDP;
  - answer a page dialog — the host that showed it answers its own way: managed Chromium with `Page.handleJavaScriptDialog` on its service session, desktop with an agreed native answer (for `beforeunload` — by repeating the held leave). The answer travels past the engine queue: a navigation held by `beforeunload` holds the queue until the dialog is answered; a declined leave answers the navigation with `navigation-failed` (`net::ERR_ABORTED`);
  - life events: opened (with opener), details changed (URL, title, favicon, loading, history), page process changed, unresponsive and responsive again, crashed, closed, dialog opened (for session-less pages), file download started and finished, host lost;
  - `session(page)` → CDP session: command → answer, command without waiting for an answer (`post` — input release on interrupt, which must not wait for a hung renderer), an event stream, nested frame sessions (OOPIF) with flatten `sessionId`, disconnect; typed `taken` when DevTools takes the debugger and `released` when it lets go;
  - `paint(page)` — scoped hold: a holder gets it when the page has a ready frame, and while at least one holder lives the host draws the page with no showing and no background throttling; the host counts holders itself. A session alone does not draw a page: an agent-driven page need not be drawn. The engine holds `paint` for the length of a screenshot and element picking, screencast — while the page has a viewer. Windowless managed Chromium always draws, and its `paint` only checks the page exists.
- Host refusals are `host-refused` with the adapter's reason and unblock; the core does not list adapter codes. A lost host distinguishes whether the call left: an unsent call refuses with `host-away`, one sent and left unanswered — with `outcome-unknown` (unblock: take a snapshot and check whether the call worked before repeating); there is no silent retry. The core tells apart the same way a CDP command whose session ended while the answer was awaited; the exception is a session detached (`detached`) from a page that lives: the host moved its target, the old target is closed, and the action repeats on the new session, because commands that left for the closed target never touched the new page.
- `ProfileHost` — a profile on a host: prepare storage and identity before the first page; `session(profile)` — a profile CDP session not bound to a registry page (on desktop — a hidden service `webContents` in the partition, on managed — a browser target in the profile context); wipe storage on delete.
- A profile deleted or cleared while its host is disconnected is marked; the host wipes storage on next connect.
- `Host.native` — a host's pages have a native view, and view bounds set their size: the engine uses it to decide whether a screencast viewer can set the page layout.
Screenshots, cookies, screencast, and element picking go through CDP and live once in the core. Printing to PDF is a `PageHost` action with one contract: Electron uses `webContents.printToPDF`, managed Chromium uses `Page.printToPDF`. That command is missing from CDP on Electron 44.8.0 although the native API works. Any other action missing from some host's CDP likewise becomes a `PageHost` action with one contract on all hosts.
- **CDP payload** is opaque text. Adapters and the channel read only a narrow header (`id`, `method`, `sessionId`), while large results — the accessibility tree, screenshots, response bodies — are parsed by the engine worker: synchronous parsing of multi-megabyte JSON on the server event loop is forbidden ([[7a910861|event-loop rule]]).

**Engine.**
- **One session per page.** The engine holds one CDP session per page and multiplexes it to all its consumers — agent actions, screencast, element picking, later the outside endpoint and DevTools — with a count of enabled domains. On desktop there is no other way: `webContents.debugger` has one client.
- **When attached.** A session exists when an agent drives the page, it has a screencast viewer, or element picking is on. A page driven by a thread with a running run, or being watched, stays attached: a model step between calls lasts tens of seconds, and focus emulation and buffers must outlive it. Idleness disconnects only the other pages; buffers outlive the disconnect.
- **Domains.** `Page`, `Network`, `Log`, `DOM`, `Accessibility` — for the session's lifetime. `Runtime.enable` is needed for page console and exceptions, and it is also an automation signal on foreign sites. Profile console capture `auto` (default) turns `Runtime` on for loopback or private-network pages — agent dev servers — and on any page after the first `read_page_console`; the buffer starts taking events after Runtime turns on, but Chromium may deliver saved earlier console messages, keeping their original timestamps; `always` — on every session page; `never` — a `console-off` refusal with a reason. `evaluate_in_page` goes as `Runtime.evaluate` without `Runtime.enable` — in the top frame's main world; engine service scripts go in isolated worlds via `Page.createIsolatedWorld`.
- **Queue.** Commands to one page run in order, different pages in parallel. There are no locks between agents and humans. A page the host reported "unresponsive" refuses standing and new commands with `page-unresponsive` (unblock: reload or close the page): a page process belongs to someone else, and without that a hung renderer would hold the queue forever. Each attached OOPIF has its own probe and contributes to the page's responsiveness; a healthy main renderer does not clear its hang. A hung OOPIF refuses in-place reload because a late debugger may not control it and terminating a shared renderer could affect other pages. Its unblock offers another profile or waiting for the profile browser to end, naming live same-profile pages and who opened them; an agent closes only its own pages and asks the operator about the rest.
- **Links.** A link is issued once per (frame target, document generation, `backendNodeId`) triple — `backendNodeId` is unique only inside a renderer process — and is reused by every later snapshot and pick of that document; a pick and a snapshot speak the same links. An old-document link refuses with `stale-ref` on a failed `DOM.resolveNode`, not on the error text.
- **Snapshot.** The accessibility tree of the main frame and nested frames as compact text. The engine walks it node by node (`Accessibility.getChildAXNodes`, several requests ahead) only up to `limit` lines and answers `more` when the tree continues; there is no full line count. The reason: the "unresponsive" probe stands in the same renderer queue: `getFullAXTree` on a 24K-node page took 3–8 s in one command and held the probe past the threshold, so the engine refused its own snapshot with `page-unresponsive`; a single walk command takes up to ~0.3 s (measured on CfT 151, one sample, loaded machine). A snapshot's price is the command count: on desktop each passes through main (300–650 commands per second and ~0.1 s per response megabyte, browser-desktop measurement), so a heavy page's snapshot is taken in parts through `within`. Before the walk the snapshot waits for the sessions of already-found other-process frames to attach.
- **Actions.** click, double click, hover, fill, type, press, select, check, uncheck, scroll, drag, upload, focus — by link or coordinates. Before a click the element scrolls into view and the point is checked to land in it; otherwise `element-obscured` names the covering element. Keys follow a US-layout table with correct codes, text goes as `Input.insertText` in chunks. Input does not steal OS focus: `Emulation.setFocusEmulationEnabled` on the driven page, otherwise the agent would intercept the human's typing in the chat field. An agent upload is `DOM.setFileInputFiles` with checkout files.
- **Emulation.** Viewport size, device, color scheme — for an agent checking its own dev server. A natively viewed page takes its size from the view bounds; emulation on it runs only on the agent's explicit call and is removed by it.
- **Capture.** A visible-part, whole-page, or element screenshot reaches the agent as a picture, as `read` delivers images; PDF is a file.
- **Console and network.** Ring buffers per page with a byte limit; reads with `limit`, level and URL filters, and `total`; a response body on request, with a limit.
- **Downloads.** Page downloads live in its record (name, path, size, state), the last fifty; the agent reads the list newest-first with `limit` and `total`, plus the file itself.
- **Dialogs.** On managed Chromium `alert`, `confirm`, `prompt`, and `beforeunload` arrive from CDP. On Electron CDP reports and answers `alert` and `confirm`, but main agrees a native presentation so no second dialog stays; it shows disconnected pages through Electron. Electron 44.8.0 does not support `prompt()` and throws a page error. `will-prevent-unload` on desktop resolves synchronously: main holds the page and publishes the leave intent, and the agreed action repeats after the answer. That is no hanging CDP dialog. For a dialog published in the page state, actions other than answering refuse with `dialog-open`; the panel draws it from that state.
- **Element picking.** `Overlay.setInspectMode` draws the highlight under the pointer, `Overlay.inspectNodeRequested` yields the node. Confirmed on Electron 44.8.0; when turning the mode off, `mode:'none'` still passes `highlightConfig:{}`. The description: URL, selector, accessibility role and name, text and HTML with limits, attributes from an allowlist with secrets cut, rectangle, a set of computed styles, a cropped frame, and a link. The input is CDP, so picking matches in the native view and in screencast and never trusts page script.
- **DevTools.** While a human holds DevTools on a page, Electron does not hand out the debugger: actions refuse with `devtools-open` and unblock "page in the operator's DevTools; continues when DevTools close", and the engine reconnects on `released`. DevTools as a multiplexer client is stage 2.
- **Screencast** — in the [[eb1e2301|managed-host and screencast part]].

**Operations.**
Agent tools are operations with `tool`, calling `any`, admitting an outside caller (plugin processes); they never ask for approval, reads are declared `read`, actions `external`:
`open_page`, `close_page`, `list_pages`, `navigate_page` (URL, back, forward, reload), `snapshot_page`, `act_on_page` (action plus link or coordinates), `emulate_page`, `capture_page`, `evaluate_in_page`, `wait_for_page` (load, text, URL, element — with a deadline the agent names), `read_page_console`, `read_page_network`, `read_page_downloads`, `answer_page_dialog`.
- A page is named by id; without an id — the page the thread last worked with.
- An action answer carries the page's new state (URL, title, dialog, whether navigation left).
- Refusals: `page-unknown`, `host-away` (unblock: connected hosts' profiles; for desktop — open Tagma), `stale-ref` (unblock: take a snapshot), `element-obscured`, `page-unresponsive`, `page-crashed` (the page renderer crashed; unblock: reload or close), `devtools-open`, `dialog-open`, `console-off`, `navigation-failed` (network code), `wait-unmet`, `host-refused` (adapter reason), `outcome-unknown`. One's own process is awaited without a deadline ([[7609a86c|wait on fact]]); only site waits have a deadline, and the agent names it.
Profile operations (create, rename, delete, clear), cookie import, and page showing also call `any` and `external`: the operator asks the agent in chat, and a plugin builds its own manager.
The `browser.pages`, `browser.pick` (picked element: description and link — for chat and plugins), and `browser.screencast` feeds declare an outside caller: a platform flag adds it (`FeedDeclaration.external`, read by `admitFeed`).

**The `@runlith/cdp` kit.** A CDP-session contract (command, events, nested sessions, multiplexer), protocol types, and the primitives the engine builds tools from: the accessibility tree and links, the key table, mouse input, capture, ring buffers, node description. It knows neither Electron nor Tagma.

**Plugins.** A plugin process calls the same operations over HTTP and subscribes to the same feeds; an AdsPower-grade tool is a plugin or a section over profile and page operations. A plugin view shows no live page at stage 1.

**What the performer proves.** Engine system tests against a minimal managed host (Chrome for Testing from a known cache directory; with no binary the test fails, not skips) on test-server pages: a snapshot yields links, and a repeated snapshot yields the same nodes the same links; a link click changes the DOM; fill and type enter text, including `&` and non-ASCII; a post-navigation link action refuses with `stale-ref`; a covered element refuses with `element-obscured` and names the cover; a loopback-page console error and request show with `total`; a `never` profile refuses with `console-off`; a screenshot matches the viewport; an open `confirm` refuses actions until answered; a hung page refuses with `page-unresponsive`; a node pick yields a description and a link a click follows; an agent with a disconnected-host profile gets `host-away`, not another profile. The same scenarios run against the desktop host ([[255c4582|its part]]).
