The held runner keeps the official OpenCode separate from the Tagma server and uses the shared hosted kit: the plugin passes the callback into Relay with the source id, and an independent event stream seals the message before results return. Frozen system and catalog arrive over public RPC; the context hook excludes tools outside the catalog and returns media at the journal images' positions, because the files API carries attachments before text. The private host shares the account DB with other threads but never starts managed recovery. Continuation requires an empty inbox and a durable terminal execution, or a native fork whose own durable log shows no execution has started. The latter prefix is settled by the vendor's fork projector even when its exclusive cut omitted the source's idle marker; rejecting it on reopen would discard preserved reasoning before the first child prompt. Process-local idle proves neither state, while an unfinished conversation is restored by the existing Tagma journal road. A new session keeps its journal seed until the SDK confirms prompt acceptance: returning a cancellable run before that point has not delivered the seed. While that seed is pending, compaction refuses before reaching the engine or publishing a boundary, because the engine would summarize a different history from Tagma's journal. Requested and automatic compaction stay inside the engine session; the plugin binds requested instructions to the active compaction's inbox id so overflow recovery cannot consume a queued request's Keep. The runner reports completed boundaries and billed usage from engine events, leaving unavailable post-compaction counts unmeasured. The vendor session and credentials belong to the account; the plugin and the temporary configuration belong to the thread's scratch. The vendor's temporary root belongs to the account too: a per-thread root makes its environment instruction differ on a fork and inserts an extra history message. Native forks copy settled vendor history rather than the journal, including reasoning, provider metadata and tool-call ids. Whole copies end at the source point pinned at birth, while a cut precedes its addressed user or compaction message; inherited addresses are resolved within the copied fork boundary after the vendor's message-id remap. Post-turn compaction reports its compaction address and durable transcript tail, including a failure or cancellation that left a compaction record, so a fork born before the next prompt still copies the fold. OpenCode 2.1.3 retains the source cache affinity for a first-level fork, but `SessionAffinity.get` chooses the immediate source on a fork of a fork, so nested forks cannot promise the source's prompt-cache key through the supported API.
