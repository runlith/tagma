Probe of 2026-10-04 on `cursor-agent 2026.09.15-d2fe57e` (darwin arm64, logged in, Free plan, Auto model), working directory a temporary one outside the checkout. Raw frames (JSONL, `dir` field: `in` — client, `out` — agent, `err` — stderr) live in the scratch of the `research-cursor` thread: `acp-handshake.jsonl` (initialize + session/new), `acp-prompt.jsonl` (same plus one prompt), `acp-methods.jsonl` (authenticate, list, load, set_*, resume, fork, close), `acp-mcp-inline.jsonl` and `probes/mcpspy.log` (MCP servers in session/new); scripts — `probes/*.mjs`. One prompt to the vendor: "Reply with the single word OK and nothing else. Do not use tools.". The rest is method calls without a model.

## What was measured

**Handshake.** `initialize` with `protocolVersion: 1` answers with `agentCapabilities`: `loadSession: true`, `mcpCapabilities: { http: true, sse: true }`, `promptCapabilities: { audio: false, embeddedContext: false, image: true }`, `sessionCapabilities: { list: {} }`; `authMethods: [{ id: "cursor_login" }]`. The answer has no `agentInfo` field (agent name and version). `authenticate { methodId: "cursor_login" }` answers `{}`, but `session/new` also works without it: the login comes from the CLI's saved credentials.

**Session.** `session/new { cwd, mcpServers }` answers `sessionId` (UUID), `modes` (`agent`, `plan`, `ask`), `models` (`currentModelId: "default[]"`, 43 `availableModels` entries, option id of the form `name[param=value,…]`, e.g. `claude-sonnet-5-5[context=300k,reasoning_effort=high]`) and `configOptions` (`mode`, `model`; `select` type). The session persists in `~/.cursor/acp-sessions/<id>/` (`meta.json`, SQLite `store.db`).

**One turn.** The `out` sequence after `session/prompt`: `session_info_update` (header "OK Reply", generated by the server) and `available_commands_update` (72 slash commands), then two `agent_thought_chunk` and one `agent_message_chunk` "OK"; the prompt answer — `{ stopReason: "end_turn" }`. Latency from prompt to first thought in this single measurement was about 16 s (prompt at 498.5 s, first thought at 514.6 s on frame marks), on Auto, without tools. Neither the answer nor the stream carries `usage_update`, tokens, cost, or a request id on this turn. Thoughts (`agent_thought_chunk`) arrive even though `--print` suppresses them per the stream-json docs.

**Methods without a model** (`acp-methods.jsonl`):
- `session/list { cwd }` — works: `sessionId`, `cwd`, `title`, `updatedAt`;
- `session/load { sessionId, cwd, mcpServers }` — works: returns `modes` and `models`, then replays history as `user_message_chunk`, `agent_thought_chunk`, `agent_message_chunk` notifications plus `available_commands_update`, `current_mode_update`;
- `session/set_mode`, `session/set_model`, `session/set_config_option` — work; `set_config_option` returns updated `configOptions`;
- `session/resume`, `session/fork`, `session/close` — `-32601 Method not found`; unknown method `foo/bar` also `-32601`.

**MCP servers in `session/new` are really used.** A stdio server from `mcpServers` starts at session creation (before any prompt) and receives MCP `initialize` with `protocolVersion: "2025-11-25"`, `capabilities: { elicitation: { form: {} } }`, `clientInfo: { name: "Cursor", version: "1.0.0" }` (`probes/mcpspy.log`). This diverges from the docs, where MCP in ACP is only `.cursor/mcp.json`. Unmeasured: whether the model sees such a server's tools, whether approval is needed, what an unresponsive server does (my spy never answered `initialize`; an http server with an unreachable address did not break `session/new`).

**Environment leaks into the session.** `available_commands_update` brought 72 commands, including this machine's user skills from `~/.cursor` and global commands. There is no layer switch to turn this off through ACP — `session/new` has no `settingSources`-like parameter as the SDK does.

## Probe side effect (fixed)

`session/set_model` changes the global CLI setting, not just the session: it wrote `~/.cursor/acp-config.json` (`selectedModelVariantId`) and replaced `model`/`selectedModel` in `~/.cursor/cli-config.json` with the picked model, i.e. it switched the default model for every `agent` run on this machine (`agent about` showed Model Auto before the probe). The probe returned `default[]` with the same call; `about` shows Auto again. The `modelSelectionHistory` order and the `acp-config.json` file (which may not have existed before the probe) stayed changed. For embedding this matters: a thread's model choice via `set_model` cannot be made on the operator's machine without noting that it rewrites his interactive CLI. Whether a session model can be picked without touching global state (`--model` when launching `agent acp`, `session/prompt` with a model) was not checked; the SDK sets the model on the agent and on `send` and per docs does not write CLI global state (unverified).

## Unmeasured (one prompt spent)

- `session/request_permission` requests and exact `optionId` (docs: `allow-once`, `allow-always`, `reject-once`; my handler picked by `kind`, but the tool-free turn had no request).
- `session/cancel` mid-turn and the state after it.
- A second `session/prompt` during a running turn (queue, error, or injection) — mid-turn input unverified; the SDK has `run.steer` for it.
- Extensions `cursor/ask_question`, `cursor/create_plan`, `cursor/update_todos`, `cursor/task` and the `tool_call`/`tool_call_update` shape — there were no tool calls.
- Whether the agent would call client `fs/*` and `terminal/*` if the client declared them in `clientCapabilities`: there were no turns with tools.
- Stream granularity and behavior on break, quota error, 401, parallel sessions in one process.
- `agent --print --output-format stream-json` mode: never launched.
