The path is the provider's, never the feature's: a feature names a model, the kind of answer and its input, and `ModelAsks` routes it. `ThreadAsks` reconciles a native warm copy through the same owner’s model resolution, without constructing a request outside providers; both doors translate model failures into the shared ask refusal set and record an ask with its path, model and reported spend. Admission refusals are recorded too: a missing fresh route is unresolved, while a cold thread ask leaves unknown model and spend unknown. A wire provider answers by request. A harness whose login a wire provider borrows answers through that wire provider when it serves the same model — this replaced the catalog's `family`. Otherwise a harness answers through the program it declares (`asks.program` in its adapter package), or not at all. The kinds a model answers follow from that route and its capabilities alone, so the served catalog can publish them per model and a picker never offers a row that every call would refuse.

An explicit role setting is a promise: a model that cannot answer its kind refuses `ask-unanswerable` and is never swapped for another, because answering with a model the operator did not pick would deceive him. The setting's write already refuses such a model; the call-time refusal stays because a provider removed or disconnected later is not caught by the write. With the role empty, the default walks the decision models (for decisions), the asker's provider light model and own model at its lowest rung, the operator's saved default, then the first connected provider's light model. Each step needs the provider in the connected set `ProviderAccounts` keeps: declaring adapters discover existing subscription logins, while undeclared CLIs still need an addressed selection.

A program takes its input on stdin and only its flags in argv, so a translation batch or a compaction segment is bounded by the model's window, not by the operating system's argument limit. An adapter declares either a program it names, with its own argv, or one of Tagma's builtin runners, whose ask flags `AskPrograms` writes beside the `harness-run` verb that reads them, so one owner holds both halves of that grammar. One budget — the model's input or context less the planned output — sizes `capacity` and refuses an oversized program ask before it runs; a program model that declares no context window answers nothing. It runs as a direct child on the account CLI runner, in an empty scratch directory so no repository instruction file is read, with the selected account's environment or the provider's default one, and a per-provider bound on concurrent programs derived from the machine; an interrupted ask kills it. No total deadline bounds it: a model reading a large input at a high rung can take any time, so an ask ends on its exit, its interruption, or — for a program that reports progress, as every builtin runner does with a whitespace line on stdout per model event (`askMoved` in the hosted kit, writing through the same stream as its answer, `askAnswered`, so an event arriving while the answer is written lands after it and never inside its JSON) and a command program declaring `progress` — silence past the ask's window, measured in machine wake time. Every fresh ask has that window on both paths: the caller's `stallMs`, or the agent's idle window when the caller names none, so a decision or translation stuck on a silent runner or stream frees its provider lane instead of holding it forever. A program that prints nothing until it ends is waited for until it exits or is interrupted. An object ask on a program that takes no schema is answered as JSON text and parsed once; every object answer, on either path, is then checked against its JSON schema (`decodeJsonAnswer` in `@runlith/llm/call`, which `generateObject` uses too): an off-schema or unreadable answer is `ask-unreadable-answer`, with no repair round that would double the spend.

An outside caller, a plugin, asks through `ask_model` (`providers/askCalls.ts`): text, or an object when it sends a JSON Schema, on the model of the `ask.model` setting or the one it names. A named model that cannot answer refuses `ask-unanswerable` like any explicit role. The ask is recorded with its caller's name (`attrs.caller`), which `read_ask_usage {plugin}` sums over the activity record's window, `activity.keepHours`, for the plugin's card; no counter of its own is kept, so the figure covers only the hours the record still holds.

Compaction summaries reach programs through `CompactionAsks` (`providers/compactionAsks.ts`), which fills the core's `CompactionModels` on `ModelAsks.text` with the run's catalog pin and turns a program's refusals into the model failures the summary strategy and the summarizer chain already read — an overflow steps back to an earlier boundary, a quota falls through to the next member, a silent program is a stalled stream. A refused ask carries the account it ran on, and a failed summary carries the summarizer's provider and that account, so the run's failure names the model and login that summarized rather than the thread's own.
