**Measured on iOS 26.0.1.** A dedicated iPhone 17 Pro Simulator (402 × 874 device points, 3× pixel density) ran MobileSafari 26.0.1 on iOS runtime 23A8464. The host was macOS 26.0.1 (25A362), Xcode 26.0.1 (17A400). `idb_companion` reported build date 2026-08-17 13:12:43, arm64; the Python idb CLI used its gRPC endpoint. No Safari WebDriver session was active for these two measurements.

**Method.** `xcrun simctl create`, `boot` and `bootstatus -b` made and booted a dedicated device. `simctl openurl` opened a static page served by Bun on the host's `127.0.0.1` on an ephemeral port. The page contained a native overflow scroller (402 × 674 CSS px), 1,000 rows of 80 px, initially at `scrollTop = 1000`. A passive touch/scroll listener recorded trusted event types, timestamps and offsets; `requestAnimationFrame` recorded offsets every frame. After release and 45 stationary frames, the page posted its JSON to the same host server. This proves host loopback reaches the Simulator and a page-side recording reaches the host without WebDriver or Web Inspector. The experiment page, host and raw recordings were kept only in the measuring thread's scratch, not committed as a reproducible experiment.

**The native gesture.** `idb --companion localhost:<port> ui swipe 200 650 200 200 --duration 0.15 --delta 5 --udid <device>` produced a trusted touch sequence and a decelerating fling. In the baseline sample touchstart→touchend was 248 ms. The release offset was 1,405 px; scrolling continued for 2,547 ms after touchend, ending at 2,271 px: 866 px of post-release movement. Frame samples within successive 100 ms windows moved 133, 86, 70, 73, 71, 47, 40, 32, 27, 22, 18 and 15 px; the sampling gaps between windows mean these values are not full-window distances. The first recorded momentum scroll event was 2 ms after touchend. This one sample does not establish the reported 159–253 ms first-event delay. Repeating with the pinned current stable idb_companion 1.7.7 (2026-10-22 build) and fb-idb 1.7.7, fetched from the release artifacts with SHA-256 verification into the lane's own cache, gave a clean 248 ms touch sequence, release at 1,420 px and 846 px of post-release travel over 2,549 ms, ending at 2,266 px. Successive 100 ms frame-sample windows moved 153, 107, 87, 71, 58, 48, 39, 32, 27, 22, 14 and 15 px. The first momentum event was 1 ms after touchend. This sample followed `ui quiet 0` and had no concurrent AX reads. A preceding sample with a concurrent AX-tree read traveled 687 px over 2,839 ms; it is not the clean control. The new measurements used the same page and swipe arguments in a private device set, with the AX bridge's device automation mode enabled.

**A write stops the iOS 26 fling.** The same gesture on a fresh page released at 1,310 px after 222 ms of touch. At 118 ms after touchend, while scrolling continued, the page wrote `scrollTop = before + 200`: before 1,473 px, target/read-back 1,673 px. Every recorded frame after that write stayed at 1,673 px through the following 45 stationary frames (about 750 ms); no native momentum resumed. The baseline had continued for over 2.5 seconds. The individual baseline and write gestures differed in touch timing, so these samples prove post-release momentum and its interruption, not a repeatable 5% distance budget across separate synthetic swipes. With the pinned 1.7.7 companion and client, the write probe released at 1,385 px after 224 ms of touch; at 131 ms after touchend it wrote from 1,595 px to 1,795 px. Read-back and every subsequent sampled frame stayed at 1,795 px for the following 45 stationary frames (about 750 ms), again stopping the fling. Raw stable-release records are `record-idb-1.7.7-1.json` (concurrent AX read), `-2.json` (write) and `-3.json` (clean control) in the measuring thread's scratch.

**Only a write that changes the position stops it.** In the feed stand on the same Simulator lane (iOS 26, the 10 000-entry feed, the stand's measured-control fling), a same-value write, `scrollTop = scrollTop`, made 4 frames into momentum did not stop the fling: offsets kept decaying through and after the write, and the fling's distance stayed within the controls' spread (run.38692.1793230957489). A write of `scrollTop = scrollTop − 1` at the same point stopped it: the fling's distance-to-velocity ratio fell to 82.9 against the controls' 504–731 (run.29634.1793233862178). A no-op write is therefore not a momentum stop; a hold that avoids stopping momentum has to avoid writes that change the position. Recordings of these runs were not kept beyond the test reports.

**Page JavaScript and native input coexist.** `appium-remote-debugger` 18.0.3 connected to the dedicated Simulator's Unix socket from `xcrun simctl getenv <udid> RWI_LISTEN_SOCKET`, selected the exact page URL and used `Runtime.evaluate`, without `startAutomationSession`. With Web Inspector attached, idb still produced trusted touch input and a 2,666 ms fling covering 991 px after release; a host evaluation read the final 2,241 px offset. The Python client was fb-idb 1.1.7. `brew list --versions idb-companion` and the executable symlink identify the installed companion as 1.5.0.b2; 1.6.8 was the formula catalog's current version, not the binary measured here. An active safaridriver session instead swallowed an idb swipe: the page stayed at 1,000 px and saw no touch events. W3C actions returned success without a recording, and a subsequent executeScript request did not answer before the driver was stopped. The lane therefore uses Web Inspector for JavaScript and idb HID for input.

**Limits.** iOS 27 remains unproved. `xcodebuild -downloadPlatform iOS -buildVersion 27.0` returned `iOS 27.0 is not available for download.` Only the iOS 26.0.1 runtime is installed (7.5 GB); no iOS 27 runtime was installed and no download size was obtained. Apple lists Xcode 27 as requiring macOS 26.6 or later, while this host is macOS 26.0.1 with Xcode 26.0.1. No host upgrade was authorized. This records the unavailable supported installation path on this host, not proof that every manual runtime import is impossible. Finger-down write suppression, iOS 27 override within 1–2 frames, touch-catching-momentum event silence, a physical iPhone and ProMotion refresh were not measured here.

**Sources.** Apple's [component installation documentation](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components) documents the runtime download/import commands; [Xcode system requirements](https://developer.apple.com/xcode/system-requirements) give the host requirements. The [idb UI API](https://fbidb.io/idb-repl/built-in-idb-api/) describes duration and point spacing. These documents describe tooling; the momentum conclusions above come from the local recordings.
