The binding publishes spacer height and row positions imperatively inside virtual-core's notification; an async Svelte commit can otherwise paint the old layout for a frame. Before a write beyond the laid scroll range it grows the spacer, but an in-range correction does not rebuild measurements merely to size it. A mount flush reads its rows in one pass before applying any size, so one row's geometry write never forces the next row's layout read. The batch applies sizes from its end and publishes once. A caller may reuse a cached mount measurement only while it owns validity for that key and layout. Later changes are measured by the observer, never by re-reading mounted rows during a Svelte flush. A measurement equal to its laid estimate is still recorded: virtual-core otherwise forgets it and a later estimate can move a row that has already been measured. Measurement resolves the current index by stable key, because a DOM index can lag a changed order by a flush. Library work is untracked: a key or estimate callback reading live content must not make the effect attaching the list depend on that content and rebuild the owner on every append. The dependency patch's `disabled-end-threshold` hunk short-circuits a negative tail threshold before computing distance to the end: that distance is nonnegative, so the comparison cannot succeed, and computing it rebuilt all pending measurements for each paused-reader correction. The `keyed-reshape-anchor` hunk also preserves the reading key when a new key function declares an interior reshape with unchanged count and edge keys; the column's live ordering can move rows across the reader without changing either edge. A layout invalidation drops unmounted sizes while leaving mounted sizes to their observer, so changing diff wrapping cannot retain old offscreen heights or re-read a transition mid-flush. A caller may block scroll writes while a native gesture owns the position; the dependency patch folds that predicate into virtual-core's existing correction hold, preserving its shifted rows and total rather than adding another buffer. The caller refreshes when the predicate clears so a release without a scroll event still folds the hold. After the element has reported its position, a correction first ingests any newer native position through the core's scroll-event classification: WebKit's scrolling thread can apply a wheel before dispatching its event, and a correction based on the older position would erase it. An own write already carried in layout state needs no synthetic report, avoiding a measurement rebuild per correction. Its native readback still advances the observed baseline: input can return to an earlier position before a scroll event, and that return must not look unchanged merely because it matches the preceding event. Correction writes remain absolute and idempotent; turning them into deltas would apply repeated targets twice. The `resized-positions` hunk rebuilds positions after measurements alone by shifting the starts of later rows by the summed size change and reading sizes only at the resized indexes: a full rebuild read every later row's key and size, so each mounted row cost a walk to the end of the list. Any other change to sizes or keys — options, an edge-key change, `measure()`, a size set outside `resizeItem` together with a new key function — takes the full rebuild. Products keep their selection, navigation, retention and following decisions; virtual-core remains the scroll writer.
