Previewing a definition gives birth to no thread, picks no model for it, and connects no MCP. The parent voice includes the project grant `agent.approves` a new root would be born with; an already-existing thread's own grant belongs to its stored composition. So sizes refer to the provider-neutral JSON input schemas the definition already pins; sources depending on model, available skills, collaboration, and connections stand separately in atBirth with no invented size. These numbers must not be passed off as the first request's full bill. For the same reason the answer preview's `start` is the start breakdown of the composition the definition pins: tools with no atBirth sources, the workspace note `null`, because only a thread collects it. A thread's stored prompt is not replaced with current definitions: if its exact schemas are not stored alongside, read_thread_agent answers toolCatalog: null.
