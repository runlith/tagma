A definition selects its instruction audience with `audience`; the `reader` audience is for a thread that answers from the project and changes nothing. It is told no law, no vocabulary, no map and no graph digest, and on a read it is told the explanations over the file but no code rule and no peer writes. The caller carries the law and acts on the answer; the explanations are what a reader answers from.

Audience is never inferred from tools: `graph` and `executor` still follow the graph capability when a definition names none, and a reader holds the graph capability (for its read tools) without being a graph audience. Because the audience is the definition's, the instruction rule delivers nothing to a reader at all, not even the header of an empty set.

The built-in `reader` is a file definition on a built-in floor of declared agents, parsed by the same parser as any other, so its tools, budget and sections are checked the way a user's are. Its sections are `keep: [preamble]`: it composes its own prompt only, in every project, where dropping section by section would refuse in a project lacking a conditional section. A project or personal file cannot take the id `reader`.
