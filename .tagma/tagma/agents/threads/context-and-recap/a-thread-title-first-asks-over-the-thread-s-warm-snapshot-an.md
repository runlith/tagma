One title first asks over the thread (`ThreadAsks`): a question over the live `ThreadAsides` snapshot costs a fraction of an excerpt, because the prefix is already cached. The snapshot lives until the cache TTL (with no promised TTL — until the run ends) and is stale after a model or account change; then, with no snapshot, after one expires during reconciliation, or after a rejected answer, a fresh text ask carries an excerpt of the reader's words to the model `threads.titleModel` names, or with that empty to the default text model ([[5a94659d]]), and the reason for dropping the snapshot lands as `freshReason`. An answer is written only under the title revision it was asked at, and nothing else about the thread is checked again: a newer turn or another account while it was pending leaves a title of the conversation true, and cancelling it would only waste the spend. On an ACP thread the snapshot is the Claude session itself ([[f3949b43|side question]]): it answers with the current selection, so no model and account reconciliation applies. A model that cannot be asked refuses `generate_thread_title` with the ask refusal; auto-title keeps the random name, and the next turn with different operator words retries (the claim is released on the words' text).

Without `threads.harnessTitle` an external thread's auto-title runs as an excerpt at turn start, once the operator's words are recorded: the ACP driver — on the recorded turn start, the terminal one — on the run-start event. So the name arrives while the turn runs, like a native thread's, whose question is asked on the model's first answer. An external thread's auto-title with `threads.harnessTitle` does not start an excerpt: a generated name would pre-empt the CLI title and stay forever, because accepting a CLI title replaces only a random name or a previous CLI title. The ACP Claude runner re-reads the session file after every `assistant` and `user` message and at turn end, and sends `session_info_update` with a new `ai-title`: Claude Code writes it before the first turn's answer, and reading only at turn end would hold the random name for the whole first turn.
