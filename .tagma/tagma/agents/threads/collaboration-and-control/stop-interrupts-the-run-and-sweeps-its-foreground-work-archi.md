Stop (`stop_run`, the Stop button, `tagma stop`) and `stop_agent` on any transport enter one kernel act `ThreadStopping.stop`, with `RunExecution.stop` underneath: it interrupts the turn at the transport holding it (on `acp` — `session/cancel` of the current turn; on `terminal` — the CLI interrupt key in its PTY, [[08a1944e]]), the turn ends `aborted` with `stoppedBy`, and then the kernel calls the host port `RunSweep`. Stop's answer does not wait for the sweep: it runs after the answer, and its outcome lands as a `swept` note on the run's activity. The server hands the port to the engine at build (`makeRunSweep` in `threads/ending.ts`), and the port sweeps only foreground calls and foreground commands with `createdRun` of this run (`ThreadEnding.sweepRun`). A host without `RunSweep` declares there is nothing for it to sweep. Background work belongs to the thread: Stop, interrupt, and the end of a run keep it; Stop of an idle thread sweeps nothing. Commands without `createdRun` also stay. Background work is swept by its own Stop, archive, or delete of the thread. An established transport process stays for the next word; an ACP session opened solely by a stopped unsent launch is retired once that launch drains if no other entrant adopted it. Withdraw takes the turn back only when the thread has `history`; without it, stop merely stops the turn and does not refuse over withdraw.

Archive and delete separately free the transport resource via `ThreadReleasing` → `TransportResource.release`; that is not part of a run's Stop. The order is one for all threads: archive holds `RunAdmission` over the selected subtree, stops runs, sweeps foreground and background work, frees resources, and only stamps after a confirmed close. Batch archive rechecks running runs under hold; a new run excludes the thread from archiving and enters `working`. An incomplete command sweep — commands still held, Stop refused, or start left unresolved — leaves the thread without the archive mark; words that waited in the queue keep waiting for the reader's next word. Rest keeps one fact — the record's `archivedAt`; the kernel reads it through the host port `ThreadResting` for the affected thread (no second mirror, no walk over all archived threads): wake after settlement, wake from a lifted hold, and an automatic word from another thread (`item`) leave words queued without a run, while a reader's word (`say`, `begin`, `continue`) opens a run and lifts the archive. Delete goes the same way — stopping runs, sweeping commands and calls of every member of the tree, then releasing each member that still holds a run or a live session, read at that moment as archive reads it, then deleting the rows; an unconfirmed release keeps the thread.
