A CLI process lives between turns, so thread busyness is decided by the core run. Moving a thread into the terminal, birthing a terminal thread with an empty task and restarting an agent without continuation raise the CLI at once, with no words and no run (`TransportResource.seated`; at birth — `ThreadHandle.seat`); such a launch confirms nobody's words. The adapter does not frame empty words. A run opened with no words is a core continuation (`continue`): the adapter types the continuation instruction into the CLI, the same words the Claude runner gives on an empty prompt. It has no marker, so a `UserPromptSubmit` whose prompt matched the shape of the text typed into the run (`turn.typed`) binds to this run: otherwise a marker-less turn would open its own observed run and displace the continuation run. Typing words into a standing CLI waits for its readiness (`SessionDriver.ready`): the session is `running`, this server's input lane is open, and the CLI turned on bracketed paste — framed words are multiline, and without this mode the CLI will not take them; without the wait, words sent in the first seconds after the move were refused with "holds no lane". A CLI that never turns on bracketed paste holds such a run waiting until Stop. The scheduler opens the run before the `launch` call; the start of a CLI's own turn is recognized as `observed`. A line the operator added to the typed words belongs to the same run: a separate message identity does not change its `runId`, or the turn selection and the final report would lose words kept in the shared journal. A failure before the CLI start is sent — an account-picker refusal, another preparation refusal, an unfinished vendor cut or root preparation, a program defect — ends the session and the open run in failure, keeping the reason and a way to continue: the outcome of a launch never sent is known, so the `uncertain` state does not apply here. Everything before `launchHarness` in `SessionLauncher` is preparation; its failure ends the session itself. The failure of `Terminals.start` itself is judged by its receipt, the `harness-run:<session>` key: no key (`Unknown`) or one closed with no execution (`Settled`, how the host rolls back an unapplied start) — the start never left, the session ends `failed`; otherwise (`Pending`, `Uncertain`, `Admitted`) the start may have reached the host, and the session stays `uncertain`. The error type does not decide this. A defect (die) on either side of the boundary also lands in the operator's fault list via `defected`. The session keeps the `failed` or `uncertain` reason in `failure` and carries it into the thread row (`process.failure`). An `uncertain` session with no execution reconciles on next rise by the same key: no start — it ends `failed` as `unlaunched` with the reason that left it `uncertain`; a key whose receipt already left by expiry (`Expired`) does not prove the CLI never launched, and ends it `lost`. Such a session's run is not open in the new server's memory after a server restart, and the session's end does not close it; the core run recovery (`TerminalRuns.adopt`) brings it. If this run's CLI does not stand and there are no untyped words, the adapter does not refuse — the core cuts the refusal with a shared reason — but takes the run and ends it with the session's end: it waits for the driver that still stands (`SessionDriver.reconcile` — it may just have left the session `uncertain` and be handing it over) and raises the driver again so it reconciles the session with the run already open; a session that ended earlier it closes with its kept reason. So the run ends with the session's reason, whoever arrives first — the lease or the core recovery. The end is confirmed by the Stop hook or positive transcript evidence; a human interrupt gives `aborted` via the reader with no report to the parent. `RunStatus`, `ThreadRuns.current` (`list_agents`) and the list row read one `thread_run`: with no run the thread is `idle`, even if the process stands. A stop arriving while the CLI session has not risen yet is ended by the adapter itself: the stop mark in memory lets the launch neither type nor open a session, and `open` under an already stopped run refuses `run-stopped`. Without that, the run would wait for the core to stop it again on the next lease beat.

The adapter has three observation timers, all per-thread, living only while there is cause; there is no global poll. The third finishes the context reading after compaction ([[eb39973e]]). Waiting for the interrupt confirmation is separate, led by [[08a1944e]]. The wait: a word stood past the open run (`TransportRuns.queued`) or the profile declared the tail final (`ends.tail: 'final'`; on Claude Code `end_turn` and `[Request interrupted by user` are written only at the turn's end) — a timer for `QUIET_WINDOW_MS` after the open turn's last hook event (`turn.movedAt`; operator records in inbox and UI do not count as motion); on expiry the tail is read, and with no positive end the window repeats. So Esc in Claude Code TUI, after which neither Stop nor `idle_prompt` arrives, ends the run `aborted` via the reader. Esc before Claude Code's first answer marks nothing in the transcript: the prompt returns to the composer, and the tail stays end-less. So on a profile with a final tail whose interrupt is confirmed by screen (`tail: 'final'`, `interrupt: 'screen'`), such a turn ends `aborted` on the window's expiry via the screen reader: `PROMPT_READS` prompt-screen readings in a row with no hook event and no open run question, if the turn has not moved since the last reading. A session that reported its own start (`observation.binding.sessionId` — its id) but within the window after the last report or motion started no turn (`turn.turn` empty) and created no transcript took no words (`untaken`). This is decided inside the record on the current row, not on the snapshot the tail was read from: a `UserPromptSubmit` arriving meanwhile cancels the outcome. Such a run's unread words drop at once (`lapsed`), without waiting for the read deadline; a run with nothing else in it is revoked by the core (`withdrawn`), as on the read deadline, and one with no such words ends `aborted` via the reader. The read deadline: the word record writes `unread` with the send moment and transcript byte offset; on `READ_DEADLINE_MS` first the marker is sought (only what was appended past the offset is read, `fate(read)` goes to the run where the marker was actually read through — otherwise the word stays unread), then `lapsed`, including on an open run. Launch, queue change and hook events refresh the needed timer; `adopt` and `watch` start restore waits from the adapter row. A positive end does not close a run whose recorded words are still unconfirmed. Return to the prompt (`Notification idle_prompt`: measured on Claude Code and Grok Build, on Grok the key is `notificationType`) only starts the check: an empty tail proves nothing; profiles with no measured notification (`ends.idle: null`: Codex, Cursor, Devin, Gemini) derive the prompt return from the screen: while the run is open and silent past the window, `PROMPT_READS` screen readings in a row with no hook event between them must show the profile prompt (`promptScreenOf`), and only then is the transcript tail read — a positive end record closes the run, an empty tail proves nothing. The recognizer is declared by the profile per source, not by guess: Codex 0.159.0 — the composer placeholder `› Ask Codex to do anything` without `esc to interrupt` (tag rust-v0.159.0: `chatwidget.rs` `PLACEHOLDER`, snapshots `status_indicator_widget`/`composer_hints`); Cursor Agent 2026.10.01-e373342 — the composer placeholder `Plan, search, build anything` or `Add a follow-up` without `ctrl+c to stop` (the installed bundle, the composer component in `9969.index.js`); Devin 3000.11.3 — the placeholder `Ask Devin to build features, fix bugs, or work on your code` without `esc twice/again to interrupt` and `Guide Devin while it works` (installed binary strings; after the end and after the turn interrupt it is on screen again — live frames 2026-10-21, [[4776e930]]). If the operator typed a draft into the composer, the placeholder is hidden and the return is not recognized. Exception — Cursor: its prompt is also the composer line `→` with text but no `ctrl+c to stop`, because the prompt returned after an interrupt hides the placeholder too, and clearing waits for exactly this screen ([[08a1944e]]). Gemini has neither a transcript reader nor a measured turn, so the screen is not read: the run ends on the Stop hook or the next turn's start. The tail window carries the vendor turn id (`TailWindow.turn`), and the Codex judge skips other turns' records: Codex writes the next turn's `task_started` before its `UserPromptSubmit`, and a turn that ended in error (`task_complete` with `error`; on the limit — `codex_error_info: usage_limit_exceeded`, [[b828138c]]) sends no Stop. Without that, the next turn's start would close such a run with no proof, as `completed`, and the refusal class would be lost. Words typed in the Stop hook's window arrive with the already ended turn's id (Claude Code, T3): the adapter remembers `lastTurn` and binds such a turn with no id so its own Stop ends it. A marker read in such a new turn lifts the word from `unread` of the run it was typed into: otherwise the word would hang unread until the read deadline and drop, though the CLI read it. The read deadline is not cancelled by an unavailable or partial transcript: words close, and the weakened-evidence reason goes to the journal. On server start the adapter reads standing sessions in one request together with the running-run flag (`sessionsStanding`) and reconciles them with the host in one `Terminals.recordsOf`. It takes the lease and raises sessions with a going run, a departed process, in transition, and all adopted ones (`adopted`: their process is a job inside another's shell, and only the driver reconciling the witness job sees its leaving); an idling live session is raised by its first use — the first hook of a `running` session with an execution (`SessionLease.heard`; a turn started by a human right in the TUI would otherwise stay with no input lane to answer the screen question), `SessionDriver.ready` before typing, `launch`, `stop` — or by its process end, awaited by the waiter with no database calls. A lease still fresh from a departed server passes on expiry at rise (`takeOverAtExpiry`). Observation timers recover only on sessions with an open turn or unread words, the confirmation wait only on sessions with the interrupt mark. So start cost grows with going runs, not with all standing CLIs. Heartbeat does not reread a thread facet whose due part (the session-root witness) is already met.
