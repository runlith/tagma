The thread journal is the truth, and the CLI session is brought to it by alignment (`makeSessionAlignment`, `sessions/alignment.ts`) — on every launch, before typing words, and between turns after an act over history. The decision is a pure function `alignmentOf` over the facet, the map header (`vendor_session`), the cut point over the `vendor_turn` rows, and the vendor cut port (`launch.cut`):
- **Keep** the root, if there is no point.
- **Cut** the X root with the vendor: from the point — the address of the first cut run; for a fork child — the origin from the header (root and address; with no address — whole). If the child already pulled out the copied turns, the cut runs in the same root at the first of them, and with no address — a new session.
- **Carry** the vendor session when the header names an account other than the one the launch runs under, and the vendor declared session files under the account folder (`launch.carry`: on Claude Code — `projects/<project>/<id>.jsonl` and the folder next to it, on Codex — the rollout under `sessions/`). The transcript is copied, not the entry: both accounts' folders are named by `HarnessAccounts.launch` (an account with no directory is the CLI default), and files are written over, because the fresh conversation sits in the header's account. The replaced generation's header moves together with the current root: the account in the header is one for all generations, and a restore that returned X after the carry would otherwise resume a session missing from the new folder. Codex looks for rollouts only in the day folders its thread-id time points at (uuidv7), not across the account's whole history. The record after copying moves the header to the new account only if it still names the old one, and the decision is made again — then the usual "keep" and "cut". An old account that cannot be named for launch, missing files, or a copy failure give a new session with Tagma seeding and the `uncarried` reason.
- **A new session** with Tagma seeding — where there is no cut: the vendor has no port for this side, the cut is not a suffix of the session, the run has no address, the session from another account cannot be carried, or the session is older than the map and the rollback reached a run with no row. Its own X becomes the replaced generation: a restore returning exactly these runs brings the thread back to X. Rows are replaced by journal-standing runs with no address.

A cut decided by one record executes outside it, so record Y judges the decision again in its record: same root, same first cut run, same side. If the journal changed in the meantime — a restore returned the cut runs, or another rollback arrived — Y is dropped and the decision remade; a dropped Y is read by nobody. `Prepare` (Claude Code, Codex) cuts before the CLI launch, and every attempt is its own prepare process with its own operation key: a repeat after a failure cannot re-ask a start whose stdin is already gone. One record sets `sessionKey` = Y, cuts the rows, leaves X the replaced generation and rewrites row addresses by Y's turns; on a turn-count mismatch the rows stay address-less. `Launch` (Grok) cuts with the launch itself: Y pins the first admitted hook whose root is the assigned id, and the same decision check stands there. If the decision changed, Y is dropped: `sessionKey` returns to the thread's own root, and a fork child keeps it empty. A CLI standing on Y is stale from then on, and the next alignment raises it again.

A branch inherits the source thread's account choice, not the account of its running process: following the default remains following it, while an explicit account remains explicit. The child header separately keeps the source session's account; if the child rises under another account, alignment carries the origin root into its account folder and cuts there, and where carry is impossible it gives a new session with Tagma seeding, not a launch refusal.

A Tagma-seeded session gets the conversation once, in a `SessionStart` context: the receipt hook carries `seeded`, the hook asks `guide_harness` of the `seed` kind with the place the orientation left within the profile hook context limit. The answer decides, the record lifting the flag: of two simultaneous questions only the one that lifted it gets text, so `/clear`, compaction and hook repeats do not reseed. History is read with no attachment hydration, split into turns by the messages that open a turn, and text is built from the end and only for turns that enter — work is bounded by length, not thread length. The `history-seeded` diagnostic is written only where a vendor carry or cut was laid down and never happened; on a CLI with no port seeding is the declared accuracy (`copies: record`), not a failure.

The map row is written by the hook with which the CLI took the run (`turn.turn` appeared): the address for `reads: 'turn'` is the turn id, for `reads: 'transcript'` the transcript window parse before the turn offset taken by `watch.mark`. A run the CLI never took gets no row and does not touch the vendor session. The thread's `copies` capability (`vendor`/`record`/`none` on the "whole" and "to turn" sides) derives from the port and is redeclared by every launch; a hook-less plain session is seeded only by whole-cut `Prepare`, with no map.

A standing CLI is stale when the root it stands on (the binding, otherwise the argv root) differs from `sessionKey` — including when the binding named a root and `sessionKey` is empty — when the map is erased under a known root, or when the decision is to cut its own root or replace it. A Launch cut awaiting binding is stale only once the decision no longer matches it (the same check as at binding): otherwise every such launch would count as stale. `SessionDriver.aligned` raises such a CLI: one alignment per thread at a time, called both by `moved` after the act and by the turn launch before its words are recorded, so words are never typed into a CLI still holding pulled-out turns. An act arriving while the CLI launches is not lost by alignment: it waits for the session to rise and judges it after. So a CLI whose Launch cut the act made wrong is raised again at once, before binding and before any words typed straight into the TUI. Alignment reads the composer, stops the CLI only if the thread has no turn in the same record, seats it again and types the read text back with no Enter. An admitted session (a job in another's shell) is not closed by Tagma: the next launch aligns it.

A fork child gets in its birth record the source's terminal seating, a copy of the rows to the point, and the origin, and `branch_thread` seats it at once: this seating is the cut. A whole-thread fork with a going turn arrives here as a cut before that turn — so the core decides: the address comes from the going run's row, and with no row (the CLI has not taken the turn yet) the child seats a new session with Tagma seeding, because session X is still being written by the CLI at that moment. Spawn with fork from a terminal thread into a child of another transport does not cut the session: the child is assembled from the journal.
