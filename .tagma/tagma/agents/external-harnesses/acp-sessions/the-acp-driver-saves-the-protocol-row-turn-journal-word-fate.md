Every durable ACP machine step (`ProtocolSteps.saved`) is one machine write: the `protocol_session` row, turn journal records and the turn end as kernel `RunReports` reports via `ProtocolJournal` (turn start with words and boundaries — `recorded`, a finished model request — `measured`, the end with remaining spend and cost — `ended`), inbox envelope fates via `TurnEnded.delivery` (confirm on `accepted`, return on `refused`, nothing on `unconfirmed`) and on extension answers, and the session facet. Every extension and `_tagma/*` notice is one declaration in `protocol/methods/`: a pure handler over the row returns a new row, reaction events, journal boundaries, agent-read words and inbox fates (a confirmed, returned, unconfirmed or recalled steer, a lifted compaction barrier), and `saved` hands it every `ExtensionAnswered`, `RequestFailed` and `Extended` of its method in one place and applies the fates in the same write. Declaration tables are total maps over the `extensions.ts` method sets, so a method with no declaration fails typecheck; an answer to a method missing from the table counts as noise and never wakes the prompt. So the durable answer — steer, compact, fork, rewind — is never lost between answer and write and survives a server restart with no repeated question to the agent. An aside answer is live and never written to the row: `saved` hands it to the waiter only after the step write passes. A request whose answer the row awaits is keyed by the id the client machine issued (`act` answers `request`), never by a predicted counter. Frames go to stdin only after it, and the host receipt returns into the machine: `Admitted`, `Unwritten` or `Unknown` — the last makes the request indefinite and the work `unknown`, and is never retried. Turn words are written once: on the prompt's `Admitted`, or — with a lost host receipt — before the agent's first saved evidence of receipt (a message, call, question or accepted turn end). An unaccepted prompt never touches the journal. A turn's open text lives in the run tail (`thread_run.stream_tail`), like native: the driver timer saves the step on `tailDue` without sealing the message (`persist(…, false)`), while the interrupt step writes the tail at once on the cancel receipt (`tail` of the plan). A report carrying one tail is keyed separately from the same step's context-read report (`|tail`): a cancel with no new frame after `usage_update` would otherwise repeat its key with a different digest, and `Cancel` would never leave. A timer-sealed message would have cut the answer mid-turn and, after a fall, left the turn with no tail — no interrupt row. Recorded boundaries and applied inbox fates publish to the live feed independently of facet change: a tool call or message may change the journal while a word's fate changes the thread's waiting words, with no session-state change. One stdout portion's frames pass in one step — one lock and at most one write — up to and including the frame that produced the event the driver reacts to (open, config or extension answer, request refusal, question, call end, turn end); the portion's remainder goes in the next step. Otherwise the reaction would see the state after the whole portion: session readiness, for example, would have been declared ahead of a config refusal from the same portion.

A turn is the aggregate's `thread_run`, and the kernel opens it: the scheduler creates the run and, after commit, calls `TransportRuns.launch`, while the driver never opens turns itself. `launch` records the hanging prompt under the id the kernel named, in the same `saved` step; a turn opened before a server fall that never reached a prompt is launched exactly once by `adopt`. The turn end closes the run (`RunReports.ended`) in the same write as `TurnEnded`: the protocol row stores no end. The parent report goes via the settlement outbox, as on a native run, and no one else's; settlement runs outside the driver transition lock. The kernel beater beats runs on the driver's `holds`, and on clean shutdown the kernel itself hands over every held run as handed-over, spending no crash-recovery attempt. A run awaiting an answer never reaches the reaper: after session capture the new driver takes it over via `RunOwnership.resumeParked`, spending no crash resumes, and restores awaiting from the durable question. A dead owner's run the reaper hands to `TransportRuns.adopt`: the driver adopts the turn via `RunOwnership.adopt` if the session stands and the recovery limit is unspent; refusal or a spent limit ends in cut. An absent or unreachable execution host, or a lost connection to it, closes the drive's lanes and pauses its link while retaining the indexed turn holds. It closes the old live tail before rebuilding, restores saved tool inputs, and replays the active text from the row, so neither text nor kernel heartbeat ownership is duplicated or lost. The drive retries without spending a kernel recovery attempt. Other drive failures, except interruption, mark the session `uncertain`, write the failure to the operator error list, stop holding the thread's turns (`ProtocolLaunches.drop`, the dropped link) and close their live tail. Step live deltas apply before their write, so a dead drive's tail may run ahead of the saved cursor. A new drive rebuilds the tail from the row and the run's saved tail, and stdout replay from the cursor never appends text twice. Watch, after its fiber exits, hands the active run to the kernel (`RunOwnership.dropped`) from a separate fiber: `ensure` on turn restart would have dropped the watch that calls it. Recovery is single per thread and lives until the kernel-accepted decision, repeating the refusal over a lease turn; a new watch awaits its end before raising a drive again. Otherwise the watch could spawn new recoveries while old ones still repeat the refusal. The kernel drives it with the same `adopt`, counting a recovery attempt; the new drive re-reads stdout from the saved cursor, and a spent limit ends the run in cut with the driver failure as cause. Without this, `launches.leading` and the beater would hold the runs while the reaper never adopts its own runs, and the turn would stand `running` forever.

The row outlives the agent process: cursor and machine reset on a new execution, while reports, the launch counter, write refusals and recap cross into the new one. The vendor turn map — `vendor_turn` rows (run, ordinal, cut address — on Claude the prompt uuid) — is stored apart from the protocol row, and its `VendorTurns` owner (`store/turns.ts`) is shared with the terminal ([[11b4f93a]]); a turn's cost is its run's fact, `thread_run.cost`. Stopping the process never deletes the map, and current-turn steps never reread or rewrite history. Fork copies the chosen prefix. A new session of any origin replaces the thread's rows with the journal-standing runs' rows, addressless, in the same write as `session/new`: the address never points into another's conversation, and the rows name every turn the session got from the journal. Rewind and Stop with withdraw are cut by the journal itself, while the vendor session is brought to it by the next launch ([[66a5c66e]]): `_tagma/rewind` from the old `sessionKey` if the cut is a uuid session suffix, else a new session from the journal in the same process. The `_tagma/rewind` answer in one write sets the new `sessionKey`, cuts the rows and leaves every row of the old session as a replaced generation (`vendor_session.replaced`: one, the last); while it is in flight the row holds `cut`, a refusal leaves `cut` with no request, and the next launch assembles the session anew. A restore returning exactly the runs this generation cut stops the process and in one write returns the thread to the old session — its `sessionKey` and rows; the vendor fork never touched it, so the next launch raises its resume, with no new session, and nobody ever raises the cut copy again. A restore whose runs were cut otherwise, and foreign compaction, stop the process and drop the `sessionKey`. An old execution with open turns or questions still open first closes as `Exited` over the old state. An unreadable protocol row ends the session with `session-unreadable` and fails its current run — including one awaiting a question answer — keeping the original record for diagnosis; repeated recovery never launches it. A stdout subscription closed by its client reconnects from the saved frame cursor. An absent or unreachable host, or a lost wire, is retried from the last received byte within the same parser; a partial frame stays intact. A gap ending probes the record's retained floor before advancing the cursor; the ending alone carries no byte address. Host-side `unavailable` and a `record-lost` refusal mean the output is gone and end the session through its ordinary process-exit road. A subscription that ended `completed` also stops the agent execution before the driver awaits its end: stdout EOF never promises process exit, and an agent that closed stdout and stayed alive would otherwise hold the turn with no frame writer and no cancel forever. Stopping an already-exited execution answers with its end receipt. A halt reads its stable operation key before acting. A settled stop without a receipt was never sent and advances to the next attempt key; an indefinite or admitted stop is read by its own key until the execution ends. A key conflict is never proof of an execution's end. Explicit restart is a separate stop intent, keyed by the restart entry, so an older indefinite halt cannot block replacement. The launch number enters the start operationId, so a start whose answer was lost is re-asked under the same key and never births a second process holding the vendor session.

An indefinite prompt awaits a late answer no longer than the profile grace: the execution process holds one timer per such prompt from the moment the row marked it, never from the heartbeat tick — otherwise the term would stretch to two heartbeat intervals. The profile grace and idle term are overridden by `ProtocolDriver.make` (`graceMs`, `idleMs`), which is how the test rig shortens them. The driver starts the execution and watch fibers on the clock taken at its own creation, not the caller's: the kernel opens the turn in its own context, and otherwise idle term and grace would run on foreign clocks. Expiry closes the process and fails the run. A session end (`finish`, `unreadable`) reads the thread's unconfirmed words from the inbox, not from the protocol row `Exited` already cleared: any past turn's words count too. They pass the shared `RunReports.lapsed`: the word is confirmed, the sender gets one report, the request is closed, a run carrying only those words is recalled. A repeat writes nothing, words are never resent. A known host refusal to write the prompt fails the turn with words returned and restarts the process once; a second in a row ends the session `failed` with the host cause; a host refusal counts in the same `rejections` tally as an agent refusal before the first update. A launch refusal counts the kernel gate: `RunReports.refused` goes first in the same write, ahead of word fates and `ended`, and the turn-start step and the refused-turn step never confirm the launch (`unconfirming`) — otherwise the next prompt's write would zero the two-refusal count and a third run would open. Two agent refusals in a row before the first update also end the session: words stay queued, the cause comes from the agent's error, no new turns start by themselves. The frame order, turn-input cutoff by cancel, and receipt parsing before `Exited` are held by [[6bfa7543|the frames queue outside the transition lock]].

A turn on `acp` is identified by the turn id: `turnAnswered`, the question (`runId`), `current`, `stop(expected)` and `sessionEnded` are keyed by it. Hooks stay silent on this transport; the judge yields the `verdict`, and the driver parks the question, holding one question in the facet and the rest in the row. The kernel `interrupt` never takes the transition lock and writes nothing itself: the kernel holds the stop intent, and the driver puts `session/cancel` at the writer queue head ([[6bfa7543]]). That frame's `Admitted` receipt under the lock is one step: the client machine marks the prompt cancelled, the turn tail is sealed, the turn ends `aborted` with the kernel's `stoppedBy`, and the sitting question is dropped as `cleared`. Only then does `interrupt` answer `interrupted`. The agent's answer about the interrupted turn arrives later: its messages and calls are never journaled again, its spend lands on the ended run ([[c2ddbc0a]]), the next prompt awaits that answer, and the snapshot shows awaiting with the `stopping` cause, not a running turn. With no link to the process `interrupt` attaches it at once, never waiting for the takeover beat; the cancel then leaves as the new link's first frame in the same `Recovered` step. No process or turn in the row — the answer is `no-turn`; a turn whose prompt is cancelled but whose agent never answered the cancel stands in the row, and a repeat stop sends it `session/cancel` again. A turn that never reached a prompt closes its opening words, and withdraw returns them to the draft. An unsent stop fences and drains the whole launch, including attendance and a pump queued behind the drive, before closing the run, then retires only a session that launch created and no other entrant adopted. Cancellation releases that queued pump: otherwise its drain could wait behind the very halt Restart must replace. The attendance wait and process retirement stay outside journal and snapshot locks: publication and the process watcher can themselves enter the journal or attend again. This also holds for a stop between the run-open commit and the driver call: the kernel closes delivered words with no remaining `delivered`. Launch acceptance and `ProtocolLaunches.issue` in one synchronous act check `RunControl.launchable` via `RunOwnership`: a stopped or ended run never releases a prompt. A turn whose prompt is already being released cannot be dropped this way — the cancel awaits the release end and travels as a frame. A late message boundary (`_tagma/said`) of an interrupted turn is skipped, and a late request measure lands on that run. A server raising the same process after a restart, with the vendor's open turn (prompt or compaction), sends `Cancel` as the first frame if the prompt is already marked cancelled (bytes may never have left) or the kernel run of at least one of the row's turns is already not `running` (the stop arrived while no server owned the turn). The watch attaches the standing process itself if at least one of the row's turns' kernel run is already not `running`. The repeat is safe: a cancel with no running turn does nothing at the agent, while without it an open vendor turn would hold `prompting` and waiting words would never leave. Vendor permission requests stand in the row's durable queue: an occupied facet slot delays the next request, and an answer or drop frees it for the oldest. Hosted-tool questions never enter this queue: `ThreadHosting` owns them, and a hosted thread never writes `facet.question`. The kernel writes the awaiting stage in `Questions`, but before it calls `TransportRuns.reached(run, 'all')`: the driver seals the unfinished message into the journal and closes the live tail, while never tracking hosted-question awaiting itself. Recovery seats the oldest parked vendor request if the slot is free (`seated`), and drops the `waiting` work when nothing awaits. Recovery re-judges the agent's saved request if the fall happened before it parked; an already-parked or sitting question is never created twice. So a permission request's raw input is kept whole only until parking or landing, then trimmed like a call input: trimmed input would give the verdict a different object. A new turn never starts while a settings or mode request hangs, including a recovery of a mode the agent changed mid-session. A lost answer confirmation shows in the journal, an indefinite question frees the slot, an unconfirmed answer is never repeated. An agent's interrupt keeps the cause as the next turn's opening word and ends the old one as `stoppedBy: agent`, so settlement reports the interrupt to the remaining customers.
