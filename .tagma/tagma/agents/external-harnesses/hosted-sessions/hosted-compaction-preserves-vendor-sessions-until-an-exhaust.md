On a `session` transport, a manual request and Tagma's fill threshold can start `_tagma/compact` in the already open vendor session with the native summarizer's instructions. Tagma's threshold comes from its settings and model catalog, and the window size from the agent's measurement. The Claude runner keeps its autocompaction off ([[d0810682|Claude runner]]); OpenCode also keeps its engine's automatic compaction and overflow recovery enabled. The same rule and the same chain as on a native thread pick the summarizer (`read_compaction_choices`, `ThreadCompactor.summarizing`), and the pick decides the road the core opens for the run (`Compactions.open`):

- **Vendor-owned (`compaction: vendor`).** Any in-session compression belongs to the vendor, which exposes no compaction API. Tagma schedules no retelling at its configured fill threshold. A manual request, including a named summarizer or compact-before-message request, refuses rather than resetting the session; a stale queued request ends failed without summarizing or resetting. Only a reported context-overflow failure, or a non-stale measurement from the ended turn at or beyond the hard context window, opens a last-resort foreign retelling and session reset. The recovery boundary names overflow as its cause. A failed turn continues through a host signal queued atomically with the successful fold; that signal explains the replacement and preserves the original failure. If that continuation overflows again, it remains failed rather than looping. With no available summarizer or a failed fold, the failure stays visible and no continuation is invented.
- **Own model** — a retelling inside the vendor session, everything below in this note: this keeps its history and warm cache. Available with `compaction: session`; Claude Code and OpenCode use this contract. OpenCode refuses in-session compaction while a restored journal is still awaiting its first accepted prompt: the empty engine session cannot summarize history it has not received, and a refusal preserves that seed rather than recording a false fold. With `compaction: foreign` there is no usable in-session compaction: the core summarizes through the configured chain regardless of cache warmth and the own-model rule. The thread’s own provider may serve that fresh summary when it answers text asks; otherwise it is excluded. An empty or unspendable chain gives `no-summarizer`; a manual pick may name another available model. The vendor-session `own` row answers `null`.
- **Foreign model** — a native core compaction run (`ThreadCompactionRuns.work`) retells the Tagma model history with the picked chain; `_tagma/compact` never goes to the agent. When the retelling is ready, the core calls `TransportHistory.restore` (`Handover.restore`) before recording the fold: the process stops, the row loses `sessionKey`, `protocol_turn` is erased, and the next turn opens a new session that the runner assembles from the folded journal. That fold's head carries the names `tool_search` disclosed before it ([[84b19bb7|core fold head]]), so the new session receives disclosed tools just as after its own model. The cut goes before the fold, as with a restore rewind: a failure between them leaves the full Tagma history without the old session, and the next turn only loses cache, while the reverse order would leave the vendor session with full context against a folded journal. Esc mid-retelling ends the run `aborted` and leaves the session alone. A run retold by a foreign model (`summarizer.own === false` in its boundary) is not handed to the transport by `RunScheduler.adopt` after a server restart: it ends cut, not with a repeated `_tagma/compact`.
- **Step.** A foreign model never compacts mid-turn: a hosted session is replaced only between turns. With `compaction: foreign` a manual step request always becomes an end-of-turn request, and the threshold on a measurement is checked after the turn. A `step` request that the rule or the name gives to a foreign model is recorded by the core with `at: end`, so only own-model steps reach the driver. A mid-turn threshold always goes with the own model.

- **Post-turn request (`at: end`).** The core decides the barrier and the moment, as with native: the request stands as a durable inbox barrier, and when the queue reaches it the scheduler opens a `compaction` run and calls `TransportCompaction.compact(run, keep)`; the driver sends `_tagma/compact` and reports the boundary with `step` and the end with `ended`. A direct request on an idling thread also writes a barrier to the inbox and delivers it into a run: `keep` survives a server crash, and `adopt` repeats `_tagma/compact` exactly once with the same instructions. Such a run is classified as compaction under both automatic and manual: its failure is not served to ordinary task customers as their work failing. The driver does not execute the post-turn threshold itself: on the measurement after the turn ends it asks the core for an `at: end` compaction, which opens the same way in automatic mode. The mode lives in the inbox request and passes to the retelling owner or the transport, so it survives waiting and restarts and never lingers as a marker on the next manual request.
- **Step request (`at: step`).** Answered `requested` with `at: step` and, while the prompt is running, goes to the agent immediately as `_tagma/compact` with `at: 'step'` under its turn's input claim (`ProtocolPrompts.stepped`). If the agent declared `_tagma/compacting`, Claude Code compacts the context at the nearest step boundary and the turn continues. The boundary is recorded into this turn, has no run of its own, and the turn keeps its classification. `_tagma/compacting` with `running: true` sets the boundary `running`, with `running: false` `unchanged`: Claude Code judged there is nothing to compact yet and will try at the next step. A `-32010` refusal means there will be no more steps. While the turn's prompt is open, the request stays under claim until the turn ends: otherwise the driver would hand it again to a turn that will not take it. The turn's end lifts the claim and the request runs after the turn. A refusal after the turn's end and Esc before compaction starts return the request to the queue immediately. A steer issued before the request goes in before the compaction.
- **Mid-turn threshold.** For a session announcing step compaction, on every `usage_update` carrying a measurement ([[c7d3d8a2|read on every request]]) the driver compares `used` against the threshold and on overflow places an automatic step request. This is decided by measurement only (`ProtocolPrompts.measured`): after a "no step happened" refusal there is no new measurement in the turn, so the request is not repeated, and the threshold fires after the turn, as before.

One declaration (`methods/compact.ts`) parses the `_tagma/compacted` and `_tagma/compacting` answers and notifications, and it alone records every compaction boundary. A notification for a request the row is waiting on sets a `completed` boundary with the retelling. A post-turn request's answer closes the run with a single record: it takes spend from the answer or from the refusal's `error.data`, sets `completed` if there was no notification, `failed` or `aborted` (cancellation is code `-32800`); the core lifts the inbox barrier when the run ends. A step request's answer carries no spend: the compaction is inside the turn's spend. So an answer that arrived before a server restart is not lost, and the agent is not asked twice. A vendor notification with no waiting request sets its own `completed` boundary in the current turn. An automatic boundary that arrives while a post-turn request waits is also independent: it must not complete that request or consume its Keep instructions. An armed in-turn request still takes the vendor's automatic boundary as its own. An extension the agent did not declare is never invoked: an already placed barrier ends failed so words behind it do not get stuck.

The boundary and the retelling join the same journal as native compaction. A vendor-owned boundary does not replace the live session. A boundary with an empty retelling — Muse Code's compaction, whose summary MSP never hands the client — is recorded without folding the Tagma model history: a fold to nothing would leave every later journal rebuild (fork, rewind, a move to another model) with no history before the boundary. When the vendor reports a retelling, the Tagma model history folds too, including the messages before the boundary in the same record: otherwise the next hosted turn would count the old orientation as still delivered and would not send world-state after compaction. The fold head carries in `metadata.toolReferences` the names `tool_search` disclosed before it (`foldedReferences`), and `discoveredToolNames` reads them on par with the native line's `toolReferences`: after `/compact` Claude Code still serves the model once-declared definitions (2.1.306: the request's `tools` do not narrow, and it does not report tools dropped after compaction), and a Tagma list narrowed to undisclosed would hand the model a tool schema whose call refuses "connected but does not offer this tool here". The native line (`compaction`) does not fit this head: its text is already a wrapped Claude Code continuation, and a Claude Code rendering onto native would wrap it twice. One request's notification and answer form one activity; usage and cost close its run with an `ended` report and outbox settlement.

Where an agent supplies a window measurement (`usage_update`), it is recorded into the thread's context reading — read by the context pill, the thread list, and composition; after compaction the reading takes the retelling's `postTokens`, and without one it is marked stale. Otherwise a hosted thread would show 0% with a full window. Cursor SDK 1.0.40 supplies only per-turn spend, not a public per-request window measurement (`usage: partial`). Its own compaction is invisible to Tagma: `onDelta` drops summary markers, stream task text carries no successful-completion proof, and checkpoint summary payloads require a private protobuf decoder. Tagma records no invented boundary or window fill; Cursor recovery can use an actual overflow error. SDK-local autocompression and its fill threshold remain unestablished, as recorded in [[81aee933]]. `/compact` in the app opens the same model menu as on a native thread for `core`, `session`, and `foreign` contracts. `read_compaction_choices` refuses `harness-contract` on `none` and `vendor`: the latter names the vendor-owned compression and unavailable API, rather than offering a cache-destroying reset. A `session` thread's own-model row is always spendable and judged by none of our quotas (`folds: session`): the vendor session folds itself, our API is never called, and its provider's `auth: 'cli'` does not matter. The spend table still judges the remaining menu rows and the named summarizer that we invoke.

The thread's automatic chain judges its members with the same `summarizerSpend` as the menu, so its own cli-model in the chain is not skipped as `not-callable`. If the first spendable member turns out to be a session thread's own model, the core resolves the pick as `own` (`summarizingOf` with the session model that `Compactions` passes), and the run goes into the vendor session; otherwise the member is foreign, and the foreign-model road runs. In such a foreign chain the own model stands among the skipped as `not-callable`: the run already goes the core road, the core never invokes it, and it never becomes the fallback member after a foreign-model failure. `chainAt` without a thread judges the chain by callability, as before: with no thread there is no session that would fold itself.
