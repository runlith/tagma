title: Operator and agents declare their agents as a Markdown file in a personal or project library; plugins bring their own
ord: 21

The operator or an agent on the operator's word starts a custom agent — with its own role, a narrowed set of capabilities and tools, a starting model, and edits of the inherited prompt — with one Markdown file, and then launches it by name like any type.

**Where they live.** Built into code (`tagma`, `rules`, CLI types). Personal — `agents/` in the server data directory. Project — `.agents/` in the project root. Plugin — `<plugin>.<agent>`, read-only, only where the plugin is on, always with the `plugin:<id>` capability of its tools.

**The file.** `<name>.md`, where `<name>` is the type id. Frontmatter: `description` (the row in the spawn menu), `extends` (a built-in agent; without it the agent stands alone), `capabilities` (narrows what `extends` holds; required without `extends`; `[]` — nothing; the set: graph, agents, files, shell, web, mcp, plugins, skills, threads, peers, resources, sandbox, worktrees, terminals, speech, artifacts), `tools` (an allowlist of names inside those capabilities), `model` (the starting provider, model, reasoning), `sections` (in order: `drop`, `replace`, `add` before/after, `edit` find/with — by the section ids `read_agent` prints). A body with `extends` is appended as an `overlay` section; without `extends` it is the agent's identity and cannot be empty.

**How.** `read_agent` — the saved (`id`) or draft (`source` / `sourceFile`) preview without launching: the assembled prompt, section ids, capabilities, the tool catalog with each schema's size, and the sources that resolve only at birth. `save_agent` — to `personal` or `project`; a `null` revision creates, the last-read revision replaces. `read_agent_library` — all floors, each definition's origin, rejected files with reasons, capability ids. In the app: the Agent library in the app menu — search, Project / Personal / Plugins groups, System prompt / Capabilities / Definition tabs, "Edit definition", "Create based on", "New agent" with an editor (name, where to save, description, "Start from", instruction text, capability flags, raw Markdown) and prompt preview. The `agent-definitions` skill explains the format to agents.

**Limits and refusals.** A change takes effect on the next thread and the next preview; running threads hold their birth prompt. A name cannot repeat a built-in agent or CLI; a personal file shadows a project one of the same name; a plugin agent beats a file of the same id. An edit whose section or fragment is gone is `agent-invalid` in preview and a failure of the thread's first run (sections depend on project and capabilities — preview in the project where the agent will work). A stale revision is `agent-changed`; a name with path separators — `agent-name`; a symlinked file is not replaced — `agent-path`.
