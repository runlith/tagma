Remove the demonstrated whole-project work from delta remeasurement while preserving debt, escapes and cold-start correctness. This implements the inspection portion of section F: measured resource use determines the isolation trade; it does not change any rule's enforcement or debt policy.

The driver already computed changed paths from its confirmed checkpoint, but `measureBound` supplied `base: null`. The declaration program therefore took its whole-reading branch. A reading can now declare `remeasure: 'delta'`, retained in its confirmed checkpoint. Only those programs receive the still-readable comparison with `mode: "measure"`; existing one-sided programs and linters keep their former request. For a delta, all current findings in the returned coverage count, including findings already on the comparison. Untouched ledger entries remain. Missing checkpoints or changed descriptions request the whole reach; a declaration reader with a missing comparison index, changed tracked reader, overlarge delta or root-wide glob/package frontier falls back to a whole reading during measurement. Ordinary landing judgements retain their explicit-preparation failure. Remeasure spans name the rule, inspection key and checkout.

Measured on one 12-core/32-GiB macOS arm64 machine, Bun 1.4.4, using `workers/reach.bench.ts` through testbed. The dataset was commit `2c34a6f957ae55a57b6f413ad211c5e72c09b11c`; the checker was this change's current source, not the incident reader. Each arm owned a fresh temporary bare Git directory and inspection store, borrowing immutable objects from the checkout without touching its measurement state. Four alternating old-form/new-form arms first seeded the same full reading, then added whitespace to one enforcement source blob. Whole reruns used 275–324 MB peak child RSS, 1.87–2.05 CPU-seconds and 59–68 MB sampled heap; delta reruns used 131–133 MB, 0.64–0.76 CPU-seconds and about 11 MB sampled heap. Wall times overlapped under high machine load, so no latency improvement is established. The four cold whole readings used 707–727 MB peak child RSS. The serving-side bench stayed around 37 MB RSS. A separate cold builtin names reading used 372 MB process RSS and 167 MB sampled worker heap. A final paired repeat after the review fixes, with lower machine load, measured whole/delta at 331/139 MB child RSS, 1.79/0.45 CPU-seconds, 56/11 MB sampled heap and 868/407 ms wall; its cold reads peaked at 697/717 MB RSS. These are one-machine samples, not ceilings or production tail latency. Heap samples can miss synchronous transient peaks; RSS and heap are different populations.
