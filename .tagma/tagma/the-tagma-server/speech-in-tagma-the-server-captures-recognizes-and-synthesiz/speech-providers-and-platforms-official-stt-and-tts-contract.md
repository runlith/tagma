# Speech providers: official contract matrix

All sources below were read on **2026-10-04**. This is read-only web research, not verification by API calls and not measurement of quality, latency, real-session cost, or SDK behavior. No checkout or graph changed; no tests or system permissions were invoked. The document is raw material for a later vendor-neutral protocol; the protocol itself is not designed here.

In the tables “unconfirmed” marks lacking read evidence, not proven absence. Capabilities attach to endpoints and models: a provider name alone is not enough. Search snippets can lag the live page; where they diverge, the directly read page is used below. Latency numbers from marketing copy are not measurements.

## What does not reduce to one flag

The following is an analytical distinction, not an additional API contract:

- **VAD**: speech/non-speech on audio; **speech start/end**: boundary events; **endpointing**: the decision to close the recognized segment; **semantic turn detection**: the decision that a thought/utterance is complete; **manual finalize**: a command to process the already-received prefix. These axes intersect but do not coincide.
- **Final** can refer to token text, segment text, whole-turn text, formatting, speaker assignment, or session end. Stable text does not guarantee a finished utterance or immutable diarization.
- **Streaming TTS output** does not prove **streaming text input**. An HTTP request with whole text and progressively delivered audio is a different contract from continuing one prosody context with new text fragments.
- **Cancel generation**, **discard queued generation**, **flush buffered text**, **close context**, **close connection**, and **stop actual playback** are different acts. Neither a generator answer nor a socket close alone proves already-delivered audio stopped sounding.
- **Language hint**, a hard language lock, automatic language choice, code-switching, and a field with a detected language are different capabilities. **Translation** is a separate operation over content, not a consequence of multilingual recognition.
- For reconnect, repeated connection, resumption of the prior server session, context restore, and replay of unconfirmed audio matter separately. The first does not prove the rest.

## 1. Soniox — STT and TTS

| Axis | Read contract and evidence limit |
|---|---|
| STT transport/auth | `wss://stt-rt.soniox.com/transcribe-websocket`; the first JSON config holds the API key, model, and audio format; then binary audio frames. A temporary API key is also documented, but the regular key suffices for a server-owned connection. An empty WS frame means end of input; the server delivers the remaining answers and `finished:true`, then closes the connection. [WebSocket API, 2026-10-04](https://soniox.com/docs/stt/websocket-api). |
| Input audio | Auto-detect of `aac,aiff,amr,asf,flac,mp3,ogg,wav,webm` containers. Raw requires encoding + `sample_rate` + `num_channels`: signed/unsigned integer PCM 8/16/24/32 bit, float PCM 32/64 bit, LE/BE where applicable, μ-law/A-law. The PCM16LE/16 kHz/mono example is an example, not proof of the only allowed rate. The full allowed STT rate range is not stated on the read page. [Realtime transcription, 2026-10-04](https://soniox.com/docs/stt/rt/real-time-transcription). |
| Partial/final | Tokens can be words, subwords, or spaces. A non-final suffix can change/disappear; each response must be read as a new hypothesis. Final tokens are emitted once and never change. `final_audio_proc_ms` and `total_audio_proc_ms` distinguish finally-processed from totally-processed prefix. This is not a plain cumulative transcript string. [Realtime transcription, 2026-10-04](https://soniox.com/docs/stt/rt/real-time-transcription). |
| VAD / endpoint / turn | `enable_endpoint_detection` turns on **semantic endpointing**, accounting for pauses, intonation, speech patterns, and context. Segment end is marked by the final token `<end>`; all prior tokens of the segment are final by then. `max_endpoint_delay_ms` 500–3000, default 2000; sensitivity −1…1 and latency-adjustment 0–3 depend on the model. Earlier finalization shrinks the context for text and diarization refinement. No standalone **speech-start** event is confirmed in the read wire API; first non-final text is not a VAD start. [Endpoint detection, 2026-10-04](https://soniox.com/docs/stt/rt/endpoint-detection), [API params, 2026-10-04](https://soniox.com/docs/api-reference/stt/websocket-api). |
| Manual finalize | `{"type":"finalize"}` fixes the whole received prefix; a separate final token `<fin>` confirms the operation. The connection stays open. The docs advise sending roughly 200 ms of silence after end of speech before finalize; too-frequent finalize can break the connection. This is a different signal from `<end>`. With diarization, early fixing degrades accuracy especially. [Manual finalization, 2026-10-04](https://soniox.com/docs/stt/rt/manual-finalization). |
| Languages / diarization / translation | Realtime recognition is claimed for 60+ languages; `language_hints`, `language_hints_strict`, `enable_language_identification`, `enable_speaker_diarization`. Speaker and language ride on tokens. `translation` supports one-way target and two-way language_a/language_b; original and translated tokens are told apart by `translation_status`, `source_language`. Translated tokens carry no `start_ms/end_ms`: word-alignment precision of source speech cannot be attributed to them. [Realtime transcription, 2026-10-04](https://soniox.com/docs/stt/rt/real-time-transcription), [wire fields, 2026-10-04](https://soniox.com/docs/api-reference/stt/websocket-api). |
| Timestamps / context | Start/end in milliseconds and confidence for source tokens; this is token-level, not a guarantee of one token per word. Structured context: `general` key/value, `text`, `terms`, `translation_terms`. The reference lists a context limit of 8000 tokens among errors. [WebSocket API, 2026-10-04](https://soniox.com/docs/api-reference/stt/websocket-api). |
| STT limits / reconnect / cost | 300 minutes per stream, a fixed ceiling; then a new session. Shown defaults: 100 requests/min, 10 concurrent; the latter two can grow. With no audio, `{"type":"keepalive"}` at least every 20 s preserves session context; >20 s without audio/keepalive can close the connection. This keeps a live connection, not a resume of prior session identity after a break; such resume is unconfirmed. [Keepalive, 2026-10-04](https://soniox.com/docs/stt/rt/connection-keepalive). Billing is for the **full stream duration**, not only VAD-passed audio. Token-based pricing: realtime input audio $2/M tokens, input/output text $4/M; the ~$0.12/hour figure is a guide, not a universal fixed price with any context/translation. [Limits, 2026-10-04](https://soniox.com/docs/stt/rt/limits-and-quotas), [billing duration, 2026-10-04](https://soniox.com/docs/stt/rt/manual-finalization), [pricing, 2026-10-04](https://soniox.com/pricing). |
| TTS input / lifecycle / cancel | `wss://tts-rt.soniox.com/tts-websocket`, config on `stream_id`, up to 5 concurrent streams on one socket. Genuine incremental text input: `text`, `text_end`; audio arrives as base64. Three separate steps: `text_end:true` → `audio_end:true` → `terminated:true`. Only the last frees the id. `cancel:true` on a stream stops it with no further audio chunks and ends in `terminated:true`; one stream's error need not close others. [TTS WebSocket API, 2026-10-04](https://soniox.com/docs/api-reference/tts/websocket-api). |
| TTS output / voices / markup | PCM F32LE/S16LE and WAV: 8/16/24/44.1/48 kHz; μ-law/A-law 8 kHz only; FLAC 16/24/44.1/48; MP3 16/24/32/44.1/48; Opus 8/16/24/48; AAC 16/24/44.1/48. Lossy takes a bitrate from the list. Voice is a built-in name or cloned voice id; language is explicitly required. `return_timestamps` is character alignment; speed 0.7–1.3; `reduce_silence` depends on model capability. Full SSML compatibility is unconfirmed. [Formats, 2026-10-04](https://soniox.com/docs/tts/concepts/audio-formats), [TTS API, 2026-10-04](https://soniox.com/docs/api-reference/tts/websocket-api). |
| TTS limits / price | Up to 2 minutes of generated audio per request: on hitting the cap the tail is truncated, the last chunk comes without `audio_end`, then an error and `terminated`. Config is needed roughly 10 s after connect; a stream with no text for several seconds can timeout; keepalive between streams every 20–30 s, but >3 minutes without generated audio still closes the socket. Input-text error cites 5000 characters. $4/M input text tokens + $21.50/M audio tokens, roughly ~$0.70/hour of generated speech. [TTS API, 2026-10-04](https://soniox.com/docs/api-reference/tts/websocket-api), [pricing, 2026-10-04](https://soniox.com/pricing). |

## 2. OpenAI — realtime transcription and Speech TTS

**Critical change in the read documentation:** the recommended `gpt-live-transcribe` requires an external turn-end decision and has no built-in `server_vad`/`semantic_vad`. “OpenAI realtime always does VAD itself” is false for this model. [Realtime transcription, 2026-10-04](https://developers.openai.com/api/docs/guides/realtime-transcription).

| Axis | Read contract and evidence limit |

[Realtime transcription, 2026-10-04](https://developers.openai.com/api/docs/guides/realtime-transcription), [WebSockets, 2026-10-04](https://developers.openai.com/api/docs/guides/voice-websockets?api=realtime). |

[Text to speech, 2026-10-04](https://developers.openai.com/api/docs/guides/text-to-speech). |
| TTS audio / voices / cancellation | MP3 default, also Opus/AAC/FLAC/WAV/PCM. Raw PCM is signed 16-bit LE, 24 kHz. The built-in-voices section lists 13, but the same page's intro says 11: go by actual model voice availability, not a fixed number. A custom approved voice id is possible. Wire cancel of Speech API and a billing-stop guarantee on abort are unconfirmed. Request-text limit, rate limits, and TTS price were not verified by this reading. [Text to speech, 2026-10-04](https://developers.openai.com/api/docs/guides/text-to-speech). |

## Interim answer to “do we need our own VAD”

**“Clouds need no VAD of their own” as a universal is refuted by the docs.** OpenAI `gpt-live-transcribe` directly requires an external commit; Cartesia Manual hands the role to the caller. The external decision can be push-to-talk, app timing, or off-the-shelf VAD: a commit requirement does not imply writing our own ML model. [OpenAI transcription, 2026-10-04](https://developers.openai.com/api/docs/guides/realtime-transcription), [Cartesia endpoint comparison, 2026-10-04](https://docs.cartesia.ai/use-the-api/stt/compare-endpoints).

**For many concrete cloud paths a local VAD for segmentation is not required.** Soniox semantic endpointing, ElevenLabs VAD commit, Deepgram Nova endpointing, Flux integrated turns, AssemblyAI end-of-turn, and Cartesia Auto perform this function on the provider side — with different speech-start availability and different semantic precision of the end. An endpoint after a pause is not identical to a completed thought; there is a latency-vs-recognition/diarization-context tradeoff. [Soniox, 2026-10-04](https://soniox.com/docs/stt/rt/endpoint-detection), [ElevenLabs, 2026-10-04](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies), [Deepgram Nova, 2026-10-04](https://developers.deepgram.com/docs/understand-endpointing-interim-results), [Flux, 2026-10-04](https://developers.deepgram.com/docs/flux/state), [AssemblyAI, 2026-10-04](https://www.assemblyai.com/docs/streaming/message-sequence), [Cartesia Auto, 2026-10-04](https://docs.cartesia.ai/use-the-api/stt/turns).

**Savings and barge-in do not follow automatically from server endpointing.** Soniox and AssemblyAI bill for open-session duration; not sending silence does not shrink it by itself. Cartesia Auto requires continuity/silence, and ElevenLabs disconnects after 15 s with no client messages. Flux TTS requires stopping actual playback locally before the round-trip interruption acknowledgement. These are reasons to first name the VAD goal — segmentation, private-audio suppression, fast local interruption, or compute reduction — rather than declare it mandatory for all or needless for all. [Soniox billing, 2026-10-04](https://soniox.com/docs/stt/rt/manual-finalization), [AssemblyAI billing, 2026-10-04](https://www.assemblyai.com/docs/streaming/message-sequence), [Cartesia silence, 2026-10-04](https://docs.cartesia.ai/use-the-api/stt/turns), [ElevenLabs silence, 2026-10-04](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies), [Flux TTS interruption, 2026-10-04](https://developers.deepgram.com/docs/flux-tts/interrupt-handling).

### Silero VAD: what is really built in

1. **An off-the-shelf preprocessing path.** The root README describes `whisper-cli --vad --vad-model …`: audio first goes through the VAD model, only found speech segments are extracted and passed to Whisper. The goal is to cut ASR compute. The current README shows Silero `v6.2.0`; this is a fact of the current page, not a claim about the installed app's model asset. [W1]
2. **Not CLI-only.** The fixed public header holds VAD config inside whisper_full_params and a standalone `whisper_vad_context`. The server example README also publishes `--vad` and the same param set, but the server takes audio files over HTTP multipart. File-request VAD support does not prove streaming endpointing of the server API. [W2][W5]
3. **A stateful streaming primitive is confirmed, also for the fixed commit.** `whisper_vad_detect_speech_no_reset(vctx, samples, n_samples)` carries the official comment: “Like whisper_vad_detect_speech, but does not reset LSTM state. Use for streaming: call whisper_vad_reset_state() between utterances.” So “built-in Silero is only good for batch” is too strong and wrong at the available-API level. [W2]
4. **Probability and segmentation are different operations.** The header separately provides `whisper_vad_n_probs`, `whisper_vad_probs`, `whisper_vad_segments_from_probs`, `whisper_vad_segments_from_samples`, getters t0/t1. One `no_reset` preserves LSTM state; the header does not promise that the same call itself runs a full multi-incremental endpoint lifecycle, finalizes an open segment after capture break, or emits stable start/end events. The returned `bool` is not explained enough to safely declare it “speech detected”. [W2]
5. **Ready whisper_full VAD boundaries are available for reuse.** The fixed header holds `whisper_full_n_vad_segments` and `whisper_full_get_vad_segment_t0/t1`, with explicit original-timeline description in centiseconds and a way to reuse internal boundaries without a second VAD pass. This proves boundary availability after processing; their readiness time with live audio is not established from the header alone. [W2]
6. **`whisper-stream --step 0` is a standalone example.** Fixed and current READMEs call its VAD “very basic”; on silence it transcribes the last `--length` ms. This does not document applying Silero/no_reset in this example. Plain `--step 500 --length 5000` regularly restarts rolling inference. Neither snippet should be called a production-ready streaming ASR contract. [W3][W4]
7. **Settings and what is unestablished.** The README defines threshold, min speech duration, min silence duration, max speech duration, speech pad, and samples overlap. Max-speech segments split at silence points >98 ms. Inference frame cadence, latency on weak hardware, exact segment-assembly continuity across calls, cross-chunk timestamp offsets, tail flush, overlap behavior, and false positives for concrete microphones are unread/unmeasured. Neither missing features nor guaranteed end-to-end turn detection can be attributed to these gaps. [W1][W2]

**Takeaway:** no separately reimplemented VAD model is needed just because the backend is whisper.cpp; Silero and stateful input already exist. The documentary reading does not establish a ready universal turn/segment state machine over these primitives and does not study how the app uses them. [W1][W2][W3]

Rate, sample representation, and channels must be read from the real buffer/format; no fixed universal output rate is established by these methods' docs. Extra encoding was not studied. [P10] |
| TTS cancel / lifecycle | `stopSpeaking(at:)` picks immediate or word boundary and returns Bool. Stop cancels speech and drops all not-yet-spoken utterances from the queue; pause allows continue. The delegate tells didStart/didFinish/didCancel apart and gives text-range/marker callbacks. Callback ordering guarantees on cancel vs already-handed write buffers are not established. [P9][P14] |
| TTS limits / reconnect / cost | Network reconnect is inapplicable to the described AVSpeechSynthesizer object API. A session/text ceiling and a separate character tariff are not published in the read docs; device resource cost and latency are unmeasured. After queue cancellation, unspoken utterances are not restored automatically. [P9][P11][P14] |

- **Google:** the current Chirp 3 page itself diverges on Recognize diarization and word-timestamp wording; 25 KB streaming request vs 15360 bytes on the VAD page; Chirp 3 HD SSML unsupported on the voices list vs the supported sync subset on the model page; streaming output enum vs fixed LINEAR16/24 kHz response description. [Soniox](https://soniox.com/docs/stt/rt/endpoint-detection), [OpenAI](https://developers.openai.com/api/docs/guides/realtime-vad), [Flux](https://developers.deepgram.com/docs/flux/state), [Cartesia](https://docs.cartesia.ai/use-the-api/stt/turns), [Azure](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-recognize-speech). | An eager boundary is retractable; it is not a final utterance. “Semantic” can mean sentence segmentation, not conversational turn-taking. |
| Manual finalization of accepted input | Soniox finalize→`<fin>`; OpenAI input_audio_buffer.commit; Nova Finalize with unguaranteed from_finalize on empty buffer; Flux ForceEndTurn→EndOfTurn(trigger=manual); AssemblyAI ForceEndpoint; Cartesia Manual finalize→flush_done; Azure preview PushAudioInputStream.Commit→CommitToken; Apple finalize(through:). [Soniox](https://soniox.com/docs/stt/rt/manual-finalization), [OpenAI](https://developers.openai.com/api/docs/guides/realtime-transcription), [Nova](https://developers.deepgram.com/docs/finalize), [Flux](https://developers.deepgram.com/docs/flux/own-turn-detection), [AssemblyAI](https://www.assemblyai.com/docs/streaming/message-sequence), [Cartesia](https://docs.cartesia.ai/api-reference/stt/websocket), [Azure](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-recognize-speech), [Apple](https://developer.apple.com/tutorials/data/documentation/speech/speechanalyzer.md). | A commit acknowledgement can be a marker, token id, final turn, separate event, or even a conditional answer. Flux STT CloseStream, unlike many drain paths, **emits no final EndOfTurn for the active utterance**. [Soniox](https://soniox.com/docs/api-reference/stt/websocket-api), [AssemblyAI](https://www.assemblyai.com/docs/streaming/message-sequence), [Cartesia](https://docs.cartesia.ai/use-the-api/stt/turns), [Google](https://cloud.google.com/speech-to-text/docs/streaming-recognize), [AWS](https://docs.aws.amazon.com/transcribe/latest/dg/streaming-setting-up.html), [Apple](https://developer.apple.com/tutorials/data/documentation/speech/speechanalyzer.md), [Flux](https://developers.deepgram.com/docs/flux/own-turn-detection). | Socket closed does not prove accepted finalization and a kept tail; input end and session end are sometimes different operations. |

## Distinctive capabilities within the read sample

- **Simultaneous source-transcript and translation tokens at Soniox**, including two-way between chosen languages with separate translation_status/source_language; translated text gets no source word timestamps. This is broader than plain multilingual STT. [API, 2026-10-04](https://soniox.com/docs/api-reference/stt/websocket-api).
- **Speculative semantic turn with explicit retract** at Deepgram Flux and Cartesia Auto; Cartesia additionally promises immutable emitted text even with the turn still incomplete. Do not carry speculative-turn semantics onto plain speech-stop. [Flux, 2026-10-04](https://developers.deepgram.com/docs/flux/state), [Cartesia, 2026-10-04](https://docs.cartesia.ai/use-the-api/stt/turns).
- **Speaker-label revision after final text** at AssemblyAI, with text/timestamps unchanged; **per-word Stable inside a mutable segment** at Transcribe. These mechanisms show different result-stability frontiers. [AssemblyAI, 2026-10-04](https://www.assemblyai.com/docs/streaming/label-speakers-and-separate-channels), [AWS, 2026-10-04](https://docs.aws.amazon.com/transcribe/latest/dg/streaming-partial-results.html).
- **Playback-aware reconciliation** at Flux TTS: Interrupt takes a session-wide playback_offset and returns spoken/remaining text. This does not replace stopping playback locally. [Flux TTS, 2026-10-04](https://developers.deepgram.com/docs/flux-tts/interrupt-handling).
- **A documented resume window at Transcribe**: SessionResumeWindow exists, but exact replay and speaker-state continuity are undisclosed by the read pages. Other cloud STT in this study establish no matching contract — this says nothing about their principal impossibility. [AWS, 2026-10-04](https://docs.aws.amazon.com/transcribe/latest/APIReference/API_streaming_StartStreamTranscription.html).
- **A time-addressed finalization frontier at Apple**, together with volatileRange and replace-by-audio-range; an explicit CommitToken at Azure preview. These are different ways to correlate the processed audio boundary and the final result. [Apple, 2026-10-04](https://developer.apple.com/tutorials/data/documentation/speech/speechanalyzer.md), [Azure, 2026-10-04](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-recognize-speech).
- **An off-the-shelf stateful Silero VAD primitive inside the whisper.cpp fixed commit**, probabilities and reusable inner segments. This suffices not to declare a new VAD model mandatory, but not to promise a ready live segmentation/turn machine. [Fixed header, 2026-10-04](https://raw.githubusercontent.com/ggml-org/whisper.cpp/080bbbe85230f624f0b52127f1ae1218247989f9/include/whisper.h).
- **On-device pipeline and runtime capabilities at Apple/whisper.cpp**: absence of a cloud key and remote billing does not prove the same support on every machine, locale, voice, and exact PCM format; this is a runtime-dependent layer, not “one more WebSocket vendor”. [Apple WWDC, 2026-10-04](https://developer.apple.com/videos/play/wwdc2025/277/), [whisper.cpp, 2026-10-04](https://github.com/ggml-org/whisper.cpp).

## Left unverified

The study measured no speed, VAD/diarization quality, timestamp accuracy, network recovery, playback cancellation, or real bills. Unconfirmed prices/limits are deliberately not filled in from memory. Conflicts of official pages are listed in the vendor sections; API experiments, installed-SDK validation, and regional-availability checks were not run. Tail close and failure recovery should be treated as unknown wherever the docs gave no explicit contract. This is the boundary of this read-only work, not a promise list for the future protocol.
