A build serves read-only a graph whose tree passed a graph step it does not know, so a step back can quietly take away the user's edits; the offer says so before the press.

- **Named at every frame, for every binding.** Composition wraps the next-installation service of whichever binding stands, release channel or checkout builds, and names the graphs on each frame it reads, checks or streams. The release channel measures its previous installation only at a refresh, so a project born since would otherwise go unnamed until the next one.
- **What the target knows is read from its server bundle**, the same way the journal return reads which form steps it carries: an issued release declares its graph steps nowhere but in its code. The scan is kept per installation root, which never changes once written.
- **Only what the step back changes is named:** a project whose main tree's marker is a step this build knows and the target lacks. A graph this build already serves read-only stays so either way and is not named; a tree with no marker yet passes the steps at its next open.
- A registry or policy read that fails leaves the offer without names and says why in the log; it never blocks the offer.
