The shared contract of tasks [[d7e0445d]], [[7374bf6c]] and [[02ce39c8]]; each changes its side only together with this text.

**Host, wire control request.** `OpenTerminalLane { claim: BindingScope, execution }` (the host takes the connection and epoch from the request's connection, as with `Input`) admits the claim into the execution under rule 39f511b4 — the lane binds to the execution at open — and registers it in the terminal stream. Answer: `{ port, token, next }` — the endpoint port on loopback, a 32-random-byte secret (base64url) and this binding's next expected sequence. Refusals are the input-admission ones plus `UnsupportedCapability` when the execution isn't pty or the host holder keeps no terminal stream. Reopening the same binding answers with the same secret. An endpoint lane lives exactly as long as its binding lives by `Bindings`' judgement — close, execution owner change, prune, custodian-epoch refusal — and no longer than the execution: when the host releases or rejects the binding, the stream closes its connection. A new connection with the same secret supersedes the old one — that is how the window reconnects without the server. The new request changes the wire shape: WIRE_VERSION 41 with corpus, and the same number carries the optional `ExecutionSummary.input` (task [[d991cca0]]) and the `Inputs` subscription ("Server" section). Schemas — `@runlith/executions/protocol/lane` (frames, close codes, `TerminalLane`, `LaneInput`), client — the `TerminalLanes` service (`open`, `inputs`).

**The endpoint.** WebSocket `ws://127.0.0.1:<port>/terminal` in the terminal stream.
- The client's first frame is the text `{"lane": "<token>"}`; the answer is `{"t":"ready","execution":"<execution id>","head":"<offset>"}`, where head is the offset the stream already read pty up to; an unknown secret closes the connection with code 4401.
- An input act is the text `{"t":"act","sequence":n,"cause":"typed"|"paste"|"raw"|"mouse"|"interrupt","act":{"_tag":"Write","bytes":"<base64>"}|{"_tag":"Interrupt"}}`; the answer is `{"t":"receipt","sequence":n,"answer":<InputAnswer>}`. One connection's acts are admitted in arrival order and don't wait for pty writes; resize and the grid stay in the control plane. An act that input rejects with a refusal (logic departure, stop, record failure — the control plane's `InputFenced`) closes the connection with code 4410: the window reopens the lane through the server and gets the refusal from there. End of input answers with an `InputEnded` receipt, as in the control plane.
- Live output is the text `{"t":"follow","offset":"<decimal>"}`; then binary frames `[offset, 8 big-endian bytes][bytes]` in order from that offset. The stream keeps an output tail at least two read buffers ahead; an offset past its start answers `{"t":"behind","retainedFrom":"<offset>"}`, the client re-reads the record through the server and sends follow again into the same connection. End of the pty stream is `{"t":"ended"}`; the connection stands while the lane stands.
- Close codes: 4401 — no such secret, 4408 — the watcher fell behind, 4409 — a new connection with the same secret superseded it, 4410 — the lane is closed or input refused the act, 1008 — a frame the lane doesn't read.
- Offsets are the `pty` stream record's offsets: the base is the record end when the logic assembled the execution, plus bytes the stream read; so the record and live output match byte-for-byte.
- A watcher that can't keep up reading (WebSocket backpressure) is closed with code 4408 and resumes from the cursor with a new connection; the stream's memory doesn't grow under it.

**Server.** Opening the window's lane after its own permission check calls `OpenTerminalLane` and hands the window `{binding, url, token, next}`. Who typed and whose view settles the grid the server learns from the host's endpoint-lane admitted-input events, not from an answer to the keypress: the `Subscribe { source: Inputs { execution } }` subscription delivers an `Inputs { binding, principal, receipt }` event for every act an endpoint lane admitted (the receipt carries sequence and cause); the keypress doesn't wait for it — the stream hands the event to the main loop asynchronously. For a lagging subscriber (credits exhausted) events merge by (binding, cause) pair: each binding keeps the last event of each cause, no more than four. So `raw` after text doesn't hide that the operator typed. What counts as typing is decided by the server; the host doesn't classify causes. Memory under a subscriber is bounded by live bindings. The subscription ends `completed` when the execution's work ends; control-plane input yields no events. `TerminalLanes.inputs` answers with the event stream only after `Subscribed`, and the server awaits that answer before `OpenTerminalLane`: the host doesn't repeat pre-subscription events.

**Window.** One connection per lane carries both input and this terminal's live output; pre-seam history is read through the server, as now. The window sends clicks and the wheel with cause `mouse`, hover and focus-report as `raw`: the operator's click is typing, their `raw` is not.
