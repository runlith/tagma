title: Shell snapshots hold evidence over file entries and drop it when a measurement is lost
ord: 4
---
`CheckoutBaselines` measures both sides of every command. A change in dirty-set membership after a HEAD move is only a candidate: `ShellRun` checks the path that vanished from the set and discards matching digest and presence before deciding authorship. A file returning to HEAD stays a shift when its bytes or presence changed. Root untracked paths with the exact name `.merge_file_XXXXXX` (six letters or digits) belong to the temporary entries of Git's external merge driver and are left out of the snapshot: they can appear in the cwd of someone else's service git process, which the bash window does not observe. A tracked file with that name stays an ordinary checkout file. Full `git status` stays the source of dirty-set membership, `rev-parse` of HEAD. Status is read in `-unormal` mode, because the untracked cache only serves the mode built by the last `git status` holding the index lock (`status.showUntrackedFiles`, normal by default), while `-uall` under a normal-cache walks every directory; the snapshot itself expands each listed untracked `dir/` directory with one `git ls-files --others --exclude-standard` over those directories, so the path set is the same `-uall` would give. `--no-optional-locks` saves neither the cache nor the fsmonitor token: status work grows with the number of directories changed since the last ordinary `git status`, not with repository size; contents are recomputed only for paths whose [[570aabee|working-file entry]] changed or is still too fresh to trust stat. In `CheckoutFlights` the frontier is split by file provider, checkout, cwd, and excluded paths; a new snapshot keeps evidence only for current dirty paths. A measurement requested during another starts the next wave — a completing command never receives its earlier snapshot.

A lost listing, an interrupted measurement, or an unread file drops the evidence: the next read takes the full dirty set and its contents again. A partial listing is never passed off as a snapshot; unread files are named as unmeasured. A file's absence is stored apart from the digest of empty contents, so deleting a dirty-empty tracked file is observed. State is also lost when one of the 32 held checkout frontiers is evicted; that limit bounds the number of unused checkouts, not the completeness of one snapshot.

`World.git` ties service reads to its world's git process. On the host the process has a scoped lifetime and a child-ledger entry; the terminal lifecycle stays with the executed command. The guest reads its own filesystem through the helper channel and applies the same stat semantics. The cost of a steady snapshot is git metadata and stat of dirty paths at concurrency 3; fresh ctimes still require a hash, and the metadata frontier stays O(dirty paths).
