## Observations: meaning and incompleteness

**Pyright and basedpyright.** Prepare accepts function/class and an import alias resolving into them. Incoming walks user code and explicitly opened program files; for an alias it is limited to the alias file. In both, `FindIncomingCallTreeWalker.visitCall` first requires a literal match of the callee name against the target name, then compares declarations. So a search by the original name cannot be treated as complete over renamed calls. Outgoing considers calls with Name/MemberAccess, resolves aliases, adds function/class declarations; a computed callee like `factory()()` gets no outgoing edge of its own. For a class, the root is its own `__init__`, not one inherited from another class. Property access also takes part in the hierarchy; that is wider than an explicit call with parentheses. Pyright's outgoing adds all matching declarations, with no exact overload pick. Sources: [Pyright provider](https://github.com/microsoft/pyright/blob/5964d828b614e0fde4a2e7312000b607e7005bd7/packages/pyright-internal/src/languageService/callHierarchyProvider.ts#L85-L249), [its AST visitors](https://github.com/microsoft/pyright/blob/5964d828b614e0fde4a2e7312000b607e7005bd7/packages/pyright-internal/src/languageService/callHierarchyProvider.ts#L323-L580), [basedpyright provider](https://github.com/DetachHead/basedpyright/blob/fa4b52d9428c0f355c95af2056cfd4edd4e6e5da/packages/pyright-internal/src/languageService/callHierarchyProvider.ts#L135-L240), [basedpyright incoming](https://github.com/DetachHead/basedpyright/blob/fa4b52d9428c0f355c95af2056cfd4edd4e6e5da/packages/pyright-internal/src/languageService/callHierarchy/incoming_calls.rs#L551-L637).

Pyright references looks for semantic declarations, not any text match; a candidate file is included if it is open, is user code, or the request came from non-user code. That is not a search of every Python file on disk. [ReferencesProvider](https://github.com/microsoft/pyright/blob/5964d828b614e0fde4a2e7312000b607e7005bd7/packages/pyright-internal/src/languageService/referencesProvider.ts#L215-L248).

basedpyright implementations scans class definitions in known files. For a class it reports assignable classes, for a method/attribute the same-named own declarations of assignable classes. The check `evaluator.assignType(baseClassType, foundClass, ..., DisallowSrcDerivedFromAny)` admits structural Protocol implementations; a direct `inherits` is not required. Libraries include explicitly opened files by default; a request from a non-user file extends the candidates. [ImplementationProvider](https://github.com/DetachHead/basedpyright/blob/fa4b52d9428c0f355c95af2056cfd4edd4e6e5da/packages/pyright-internal/src/languageService/implementationProvider.ts#L107-L255).

**ty.** Prepare resolves function/method/class and may return several overload candidates. Incoming follows the call AST and semantic definitions, counts bare decorators and property accessor calls, and disables the text prefilter for dunder. Cross-file search is limited to `db.project().files(db)` and the target's external visibility; renaming through an import alias is not cut off merely because of the call-site name. Outgoing does not enter bodies of nested function/class/lambda but counts their declaration-time expressions. Edges are built only for Name/Attribute callees with a resolved function/class definition. [Prepare and CalleeLeaf](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_ide/src/call_hierarchy.rs#L35-L190), [incoming](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_ide/src/call_hierarchy/incoming_calls.rs#L32-L113), [incoming visitor](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_ide/src/call_hierarchy/incoming_calls.rs#L217-L253), [outgoing](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_ide/src/call_hierarchy/outgoing_calls.rs#L33-L175).

ty implementations follows the nominal MRO: a structural Protocol without explicit inheritance is not found. The result includes the chosen definition of the root class/member and definitions in known subclasses; a class that only inherits a method adds no new target. Receiver type, reachability in the given Python environment, property accessor role, and stub→source mapping are taken into account. [Goto implementation](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_ide/src/goto_implementation.rs#L74-L183), [actual MRO check](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_python_semantic/src/types/ide_support.rs#L466-L563).

## Observations: headless process and resources

Pyright runs as a Node language server, basedpyright as `basedpyright-langserver --stdio`, with no editor; an LSP client is needed. Analysis lives in the service memory. BackgroundAnalysis uses a Node worker thread, not a separate OS process; the worker is created only with a supported cancellation setup, and for Pyright also not in debug mode. One analyzer per process cannot be assumed, nor that any generic LSP client automatically enables background workers. [Pyright worker](https://github.com/microsoft/pyright/blob/5964d828b614e0fde4a2e7312000b607e7005bd7/packages/pyright-internal/src/backgroundAnalysis.ts#L23-L46), [Pyright conditions](https://github.com/microsoft/pyright/blob/5964d828b614e0fde4a2e7312000b607e7005bd7/packages/pyright-internal/src/server.ts#L226-L234), [basedpyright conditions](https://github.com/DetachHead/basedpyright/blob/fa4b52d9428c0f355c95af2056cfd4edd4e6e5da/packages/pyright-internal/src/server.ts#L21-L45), [headless basedpyright setup](https://docs.basedpyright.com/latest/configuration/language-server-settings/).

ty runs as `ty server`: one native Rust process with `Connection::stdio()`, worker threads `min(available_parallelism,4)` in the entry point read; semantic operations use Salsa snapshots and Rayon. The process serves a set of projects. It receives file changes through LSP dynamic watched-file registration and didOpen/didChange; the code warns if the client does not support file watching. [Server entry](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_server/src/lib.rs#L29-L64), [file watcher](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/crates/ty_server/src/session/file_watcher.rs#L58-L72). The worker-thread limit does not prove the same overall limit for all threads of the process.

No documented universal cold-start navigation or RSS numbers for these three servers were found in the primary sources read. [Astral benchmarks](https://github.com/astral-sh/ty/blob/main/BENCHMARKS.md) publish concrete machine/version-dependent results; the [harness](https://github.com/astral-sh/ruff/blob/7a8f63f0d71a1d381f99652a5fee3b043b32e8e6/scripts/ty_benchmark/README.md#L16-L62) distinguishes CLI cold check, time-to-first-diagnostic of a new LSP, and incremental recheck. None of these metrics alone is cold definition/references latency or RSS of a headless navigation session. CLI typechecking numbers are not carried over here.

## Conclusion and unknown

Code conclusion: LSP allows one headless wire, but capabilities are insufficient for one promise of completeness. For Python, basedpyright gives structural implementations that ty currently does not look for; ty avoids the literal name gate that limits incoming in both Pyright branches. That is grounds for a separate comparison on fixtures, not a measurement of quality.

Not verified: binary launches, real answers on fixtures, cancellation latency, memory, cost of the first cross-file search, differences of installed releases, full handling of Python dynamics, monkey-patching and generated/runtime imports. No result may be read as proven absence of an implementation or call; LSP replies carry none of Tagma's required count of unlinked textual matches.
