A diff-region boundary proves no dependency: adjacent independent insertions and replacements land separately, keeping the foreign working file intact. If unowned plain-text edits stand next to the carriers' lines, they stay out of the pick, even when every known holder joins the delivery, unless the root's taking carries a matching team observation. A required unowned replacement of a recorded insertion is a dependency: without that carry, selection refuses `lines-held` naming nobody before constructing a torn slice or parsing it. `whole` and the program-file marker preserve the path's wholeness; an explicit `paths` may still pick a whole path holding only unowned lines. Links run over the record's separate splices: an edit of an uncommitted insertion carries the insertion itself, and a new file's line depends on its creation. When the creation is an observed unowned base, that link requires its remaining unowned lines too: without a matching team carry or `whole`, landing refuses before publishing a new file stripped to its recorded edits. A foreign holder, once landing takes even one of its lines, rides along with all of its uncommitted change in that file: its parts are one state that existed only whole, and a part without the rest assembles a file nobody wrote (uses without their declarations, written as a separate edit). A holder of an ended session whose line fell into the carried region rides the same way. A holder touched by no link stays out. In a cut file with foreign lines, or with unowned ones the landing leaves on disk, the code-facts language port matches unresolved picked links against working definitions by the lines' provenance coordinates; local shadowing and type/value/namespace spaces are told apart. Delivery files importing a foreign file — a file holding such lines — also become roots. In a cut file, links and spellings for the name check come from the picked slice's added lines, including automatically carried dependent lines; HEAD lines give the binding context but add no requirements of their own. A changed import source attracts the bindings it declares, even when their names stand on unchanged lines of a multiline import. Picking a whole importer still checks its entire text against foreign changes omitted from the tree. A path already carried whole is no longer a foreign dependency candidate; when none remain, no dependency parser runs. For import, namespace import, default export, and re-export, the used names are requested only from the settled Holdings set of foreign commit candidates, then judged before the binder reads them. Git-ignored targets remain outside commit dependencies even when their installed-file edits have recorded holders; their durable package-manager patches belong to the delivery instead. In an imported target, peer declarations and members of classes, interfaces and object types left out are also linked to the importer's spellings of identifiers and properties, destructuring and a renamed receiver included — only spellings the importer's own binder cannot place: an identifier bound to a declaration of the importer, or a member the binder finds on a type declared there, never links. A spelling matching such a name is then placed by a checker over the importer and the files the walk reaches from it — its direct imports and the re-export chains it follows, read as they stand, with the standard library types; a spelling that still does not land makes the checker pull in, round by round and within the same text capture, the files its receiver chain reaches through imports — the call targets and type annotations that give the receiver its type. Placement reads every file as the landing leaves it: a file whose landed text the walk did not hand over and whose standing text differs from the landed tree is not read from disk at all, so excluded lines never prove a member. It links only where it lands on the peer's declaration, and by name only where that checker cannot place it, so a receiver whose type the chain cannot reach inside the capture still links by name and may refuse too much. An imported value assigned to a type the importer declares is not followed through that type's members. Array-rest assignment member spellings stay unresolved because TypeScript's destructuring-property API cannot read that syntax; they still enter the conservative member check. Unexported top-level declarations of an instance `<script>` in Svelte never become cross-file dependency candidates; an instance `export` keeps the component consumer's public names, but named module exports are read only from `<script module>`. The script's local bindings keep checking inside the file. `lines-held` names the name, the file, and the holder; the ways out are landing the holder, `taking`, or including the required paths in `paths` and `whole`. An unowned declaration is named with the `nobody` holder: there is no one to wait for and `taking` never takes it, so the only way out is `whole`, with which the caller carries these lines into the delivery itself. Without this check, an unowned line stayed on disk while the commit carried uses without a declaration. Foreign-file checking waits for a completed Holdings snapshot: `opening` and `judging` do not yet prove foreign lines absent. Without foreign files, Holdings cuts the path short of import facts and the binder; clean import targets and chains through them are never parsed. The JS/TS binder lives lazily in the existing walk worker, with no library types or semantic diagnostics; it reads only handed texts, except placement, which adds the library types, reads the reached files and the receiver chain's files from disk, and runs only for names already matched to a peer candidate, so a landing without such a match pays nothing for it; the worker keeps the placement program's library files between calls, so only the first placement in a worker pays for reading them. Preparation and visit facts keyed path+name+meaning are reused; import facts additionally persist by path and digest of the latest version in the worker's bounded memory, while target resolution stays fresh. This is no full typecheck: languages without a port and links through clean intermediate targets stay out of range; rules and hooks keep judging the assembled tree. Ambiguous repeated lines link where separate placement would have changed the remainder's authorship. They match in the fold worker over shared history texts, so file size and edit count never hold the event loop. The boundary is provenance inside the picked paths; a cross-file delivery is set by `paths` and `taking`. Landing closes these links and names the automatically taken authors in `carried`; their lines are judged as part of the caller's delivery. The operator's lines require explicit taking. `whole` is a list of files or directories among the picked paths: it changes content wholeness only where it matched, and never picks the path itself.
