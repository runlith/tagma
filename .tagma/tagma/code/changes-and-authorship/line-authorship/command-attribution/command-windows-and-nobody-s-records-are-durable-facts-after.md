Whose command shift it is, is decided on facts, and `Lives` is only their in-memory cache. Without durable facts, a restart between a command's end and its lines being recorded lost attribution.

- **Window** (`command_window`) is inserted when the command opens, before the base is measured — so the journal knows the window from the first moment, and the nobody-mark cleanup horizon (the oldest open window) does not skip a command with a slow measurement. The pre-launch measurement adds HEAD, the dirty paths' digests, and holds their available texts by digest until the window decides. These are observed bytes, not an authorship record: overlap leaves lines nobody's. Already stored text is held without re-reading; text read from disk is accepted only on digest match. After its lines are recorded or all shifts decided, the window releases its hold ([[c851d6c3|text storage]]). On `settle`, the process life (start/end) is written apart from the measurement window, plus the observed shifts, digests only (hunk bytes are later read from disk with a digest check). A post-restart decision takes the same process life as before: the measurement window is longer, and under the "shortest life" rule it would have handed the record to the neighbor. The window is deleted when all its shifts are recorded or decided; a settle-write failure does not hold the window forever — it closes the same way.
- **Nobody's reshape record** (`command_unowned`) is a fact too. Marks older than the oldest open window are deleted when the window closes.
- **At startup** (`recoverCommands`), window lives are restored first and a hold is taken on each of their checkouts, then the record-line marks and nobody marks load: without the hold, loading a mark would immediately clean old ones. Settled windows are decided again by the same `settle` machine, and startup waits for their lines. Then the window the restart caught open is judged: a base path whose on-disk digest differs from the recorded one and is not explained by a record line after opening (a deletion is explained by the absence digest) gets `command_unattributed` with reason `restart` for the window's thread. A path unreadable in the base or now does not count as a shift; a path outside the base is honestly external.
- **Whose shift** (`Lives.decider`): a record mark (`instant`) explains a shift with the same digest when its span from intent to file write touches mtime ± WRITE_GAP or the command window. Without marks, command lives touching the write span ± WRITE_GAP decide, and without that — the window; a known span no life touched leaves the shift nobody's (`unclaimed`) instead of falling back to the window. The span is the file's own mtime when it falls in the window, else its ctime when that fell between the window opening and the "after" snapshot start: a move into place (`git mv`, `mv`, `cp -p`) preserves mtime but stamps ctime at its own moment, and without it the destination would be judged over the whole window and, next to a neighboring command, go to overlap with the move pair. someone else’s `chmod`/`chown`/xattr also changes ctime; such a change during the "after" snapshot never becomes a point, while a change while the command ran, with a live neighbor command, yields two candidates; for a deleted file — from the window start to the directory mtime: any later write in the directory (a neighbor's CAS edit, a nearby deletion) changes the directory, so its mtime is only an upper bound, not the moment. An existing file gets no bound from the directory (an in-place rewrite with restored mtime never touches it), and without its own mtime it is judged over the window. As a moment, it once gave another command's deletion to the one command that lived through a late edit of a neighboring file. A window alone never authors: a command proves a shift only when its line names the path — a literal operand, a shell pattern, or a reader's implicit outputs from the list ([[46bb0015]]). An operand pattern keeps quotes and escaping: `*` and `?` do not cross `/`, a wildcard does not capture a component's leading dot; classes and brace alternatives follow shell glob. A matched operand also names its subtree; `find … -delete` with known roots and no other writing actions names the roots' subtrees without narrowing them by search predicates. Variables, substitutions, and `~` stay opaque. Of the lived candidates, the ones that name the path decide: one thread — its shift; several threads of one tree — reason `team` with the tree root; otherwise `overlap`; an opaque writer and a reader next to them are not rivals. A path nobody names makes the shift nobody's even with a single candidate: an opaque line can write anything, as can a writer the record never sees (an editor, a CLI outside Tagma, another server instance), and timing coincidence does not tell them apart. The observation then goes to opaque writers, and without them to everyone who lived: one or several threads of one tree — reason `team`, one thread whose tree is unknown — `unproven`, otherwise `overlap`. Only a command from that circle puts a nobody shift into its `command_unattributed`; the rest, and a command the record skipped, get `unclaimed`. A single candidate with an unnamed path still counts toward its signature as a record (learned roles) but gets no authorship. Role, signatures, and the tree root are stored in the window, so a post-restart decision sees the same command. In named paths a line still means a literal subtree, and a `glob` object means a shell pattern after one brace-alternative expansion: there is no re-expansion on read, or quoted braces would become alternatives. Old-form windows read without rethinking lines as patterns. A command whose line provably writes nothing (every part `readsOnly` on `shellFacts` facts) opens a life through `Lives.reading`: it is not a writer candidate, it has no journal window, and its own judgement only names verdicts and writes no lines. There is no "wait until the shorter command decides": Tagma never sees which process wrote, and life length proves nothing about it.
- **Move pair** (`pairingOf` in `commandRows`): a deletion and a birth of the same bytes in one command, where one side is this session's shift and the other is the `overlap` of named candidates, both become the session's lines, the birth with `movedFrom`; an `unproven` side no line names never joins the pair — byte equality does not prove this command wrote it. The deletion is judged over the span from the window start and almost always lands in overlap next to a neighboring command; without the pair, `git mv` or `mv` would land as one destination, and the old file would stay in the tree. A pair is taken only on the single birth and deletion of that digest with content no shorter than `MOVED_BYTES`: an empty or single-line file matches byte for byte with no move, and then the neighbor's deletion would go to this session.
- `command_unattributed` is a durable "session's nobody paths" list, one record per path and checkout, with no cap: a cap silently dropped a large command's paths, and `paths` stopped finding them. A team observation stores the version its command observed, without assigning the bytes to any session; the root's taking can carry it only while that version still matches. File absence is distinct from an empty file, so recreating a deleted file cannot match its deletion observation. An observation without a digest grants no team carry. A path leaves the list when it became a session line through a move pair; when a landing in this checkout — of any session — found it clean after the commit (only a record older than the status snapshot leaves, so a path that fell back into overlap since stays); when the thread is deleted (the thread-record deletion event), and archived and vanished threads at startup and on the same cleanup after a landing. `read_changes` (sessions and paths) and the `paths` selection in `submit_work` read the list; per-path reads and deletes go on the `(checkout, path)` index.

A command measures the session's checkout when its workdir stands there; a command that can write measures it also from a workdir outside any repository (scratch), and from another repository when its line names it. A command that can write is besides measured, each with its own window, in every registered checkout its line reaches: its workdir, each directory it `cd`s into and each path it names (`WorkspaceChanges.checkouts`). A named path reaches the checkout of its directory record (`placeAcross`, so removing a link reaches the link's checkout) and of what it resolves to (`resourceAcross`); a path or pattern standing above registered roots reaches every root it names (`rootsWithin` filtered by `nameIn`). Before any of it the kit respells the named paths physically — directories resolved, the last name kept — because a role names a path lexically against its tree (`nameIn`): a path spelled through an alias of the checkout would otherwise name nothing in it. Without that a `cp` into a group member, or a generator run in another project's checkout, left every line it wrote there nobody's. A checkout the line never reaches stays unmeasured: a window alone never authors, so measuring it would buy no line for a reading per command. A provably read-only command measures only the session's checkout; a repository no project registers is never measured, and the command answer names the workdir's.

A path digest is over bytes. A file past the text limit is hashed by stream and judged at file level.
